★01AWS, ADOP 공개 — 에이전트가 개발단계서 ETL·품질검사·거버넌스 생성, 프로덕션은 결정론적 아티팩트로 실행Agentic Data Operations Platform (ADOP): Data engineering into hours✍️ 블로그 · aws.amazon.comAWS가 새로운 데이터 소스 온보딩에 수 주가 걸리던 데이터 엔지니어링을 몇 시간으로 단축하는 참조 아키텍처 ADOP를 공개했다.

Amazon Bedrock과 Claude Code, Kiro, Cursor, Codex 등 AI 코딩 도구 위에서 특화된 에이전트가 Bronze-Silver-Gold 전 과정을 자동화하며 ETL 코드, 품질 검사, 시맨틱 레이어, 규정 준수 컨트롤을 생성한다. 핵심 설계는 에이전트는 개발환경에서만 동작하고 프로덕션은 CI/CD로 승격된 결정론적 PySpark, SQL, Airflow DAG를 모델 호출 없이 실행하는 방식이다. 범용 코딩 어시스턴트와 달리 ADOP는 데이터 엔지니어링 스킬과 프롬프트로 범위를 좁히고 회사 표준을 설계에 내장해, LLM이 아키텍처를 자유롭게 결정하지 못하게 한다.

WHY IT MATTERS

규제 산업의 데이터 플랫폼 책임자에게는 컴플라이언스가 사후 검토가 아니라 온보딩 시점의 인라인 컨트롤로 바뀌는 것이 실질적 변화이며, 감사 가능성과 비용 예측성을 확보하려는 조직에 특히 유효하다.

WHAT'S DIFFERENT

기존 범용 코딩 어시스턴트가 개방형이라 엔지니어마다 다른 아키텍처를 만드는 것과 달리, ADOP는 프롬프트와 표준을 좁게 제한하고 프로덕션에서는 모델 없이 결정론적 아티팩트만 실행하도록 설계됐다.

01AWS, Amazon Bedrock에 쿼리 인식 압축 패턴 공개 — Claude Haiku로 청크 필터링해 RAG 입력 토큰 비용 절감Reduce RAG costs on Amazon Bedrock with query-aware compression✍️ 블로그 · aws.amazon.com이 블로그는 Amazon Bedrock에서 RAG 운영 비용을 줄이기 위한 검색 후처리(post-retrieval) 압축 패턴을 소개한다.

기존 RAG는 재현율을 높이기 위해 top-k 5~20개 청크를 통째로 프롬프트에 넣어 기술문서·법률 문서 워크로드에서 쿼리당 수천 개의 입력 토큰이 소요된다. 제안 패턴은 검색 후, 최종 답변 생성 전에 더 작고 저렴한 모델(Claude Haiku)이 검색된 청크를 사용자 쿼리와 대조해 관련 구간만 발췌하고, 이후 주 모델(Claude Sonnet)이 압축된 컨텍스트로 답변을 생성한다. 압축 호출과 주 모델 호출은 하나의 AWS Lambda 함수 안에서 실행되며, 이 패턴은 prompt caching, Intelligent Prompt Routing, Rerank API와 결합해 비용 절감 효과를 더 키울 수 있다.

WHY IT MATTERS

RAG를 대규모로 운영할 때 입력 토큰 비용이 전체 비용의 상당 부분을 차지하는데, 답변 품질을 유지하면서 토큰을 줄이는 실전 아키텍처를 제시한다는 점에서 실무 적용 가치가 크다. 불필요한 컨텍스트 제거는 비용뿐 아니라 환각(hallucination) 발생 여지도 줄이는 부가 효과가 있다.

WHAT'S DIFFERENT

기존 RAG 파이프라인이 검색된 청크를 그대로 프롬프트에 이어붙이는 방식과 달리, 이 패턴은 저비용 소형 모델을 캐스케이드로 추가해 검색과 답변 생성 사이에 쿼리 기반 필터링 단계를 삽입한다는 점이 다르다.

03LLM as Detector: An In-context Learning Approach for Tabular Anomaly DetectionLLM-Detector, LLM 인컨텍스트 학습으로 표 데이터 이상 탐지 — 24개 데이터셋서 15개 SOTA 능가📄 논문 · arxiv.org표 데이터의 이상치는 개별 특성값의 이탈보다 특성 간 의존관계 위반으로 나타나는 경우가 많아 기존 기하학적·재구성 기반 탐지기로는 한계가 있다.

WHY IT MATTERS

LLM 파인튜닝이나 별도 모델 학습 없이 프롬프트만으로 이상 탐지 로직을 생성한다는 점에서 실무 적용의 진입장벽을 낮출 수 있다. 특성 간 의존관계를 명시적으로 반영하는 접근은 정형 데이터 이상 탐지의 고질적 한계를 다루는 방향성을 제시한다.

인과추론 — 인과추론 기법, causal ML, 인과관계 기반 의사결정
01Causal Reasoning with Bipartite Graphical Causal ModelsUAI 2026 논문 — 이분그래프 인과모델(BGCM), 순환·평형 시스템의 do(X=x) 모호성 해소📄 논문 · arxiv.org · UAI 2026기존 CBN과 SCM은 피드백으로 인한 순환 인과관계를 가진 평형 시스템을 제대로 표현하지 못하며, 동일한 값을 강제하는 서로 다른 개입이 다른 효과를 낼 때 표준적인 do(X=x) 개입 개념이 모호해진다.

이 논문은 변수 노드와 방정식 노드로 구성된 이분 그래프로 시스템을 표현하는 bipartite graphical causal models(BGCM)를 제안한다. BGCM에서 do(f_j: X_v=ξ_v) 개입은 어떤 방정식이 대체되고 어떤 변수가 어떤 값으로 목표되는지를 명시해 모호성을 해소한다. 물리 시스템 사례 연구를 통해 이 표현이 실제 개입과 자연스럽게 대응함을 보이고, 방정식의 함수적 결정성을 활용한 새로운 그래프 분리 기준(B-separation)으로 마르코프 성질을 정식화하며 비무작위 입력 설정으로도 확장한다.

WHY IT MATTERS

순환 피드백이 존재하는 평형 시스템(생물학적 항상성, 경제 시스템 등)에 대한 인과추론은 기존 프레임워크의 한계로 다뤄지지 못했는데, 이를 그래프 기반으로 다룰 수 있는 형식적 도구를 제공한다는 점에서 인과추론 연구자에게 중요하다.

WHAT'S DIFFERENT
