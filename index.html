01AWS, ECS/Fargate 헬스케어 멀티모델 에이전트를 Bedrock AgentCore 런타임으로 마이그레이션Migrating multi-model AI agents to Amazon Bedrock AgentCore runtime✍️ 블로그 · aws.amazon.com이 글은 Hugging Face smolagents로 만든 트리플 모델 헬스케어 AI 에이전트를 Amazon ECS/Fargate 자체 관리 인프라에서 Amazon Bedrock AgentCore runtime으로 이전하는 방법을 다룬다.

기존 에이전트는 BioM-ELECTRA-Large-SQuAD2(SageMaker), Llama 3.1 70B Instruct(Bedrock), 벡터 기반 지식 검색(OpenSearch)을 조합해 쿼리 유형별로 적절한 모델 백엔드로 라우팅한다. 마이그레이션은 기존 에이전트 로직과 멀티모델 오케스트레이션, 벡터 검색 기능을 그대로 유지하면서 컨테이너 라이프사이클, 스케일링, 아이덴티티, 관찰성을 AgentCore가 자동 관리하도록 바꾼다. BYO(bring-your-own) 에이전트 방식을 사용해 프레임워크에 맞춰 코드를 재작성하지 않고도 기존 코드를 그대로 배포할 수 있음을 보여준다.

WHY IT MATTERS

멀티모델 에이전트를 운영할 때 컨테이너 오케스트레이션, 스케일링, 아이덴티티, 관찰성 관리에 드는 운영 부담이 커지는데, 관리형 런타임으로 옮기면 팀이 에이전트 로직 개발에 더 집중할 수 있다는 실질적 이점을 보여준다.

WHAT'S DIFFERENT

기존 ECS/Fargate 자체 관리 배포에서는 컨테이너 오케스트레이션, 스케일링 정책, 아이덴티티, 관찰성을 사용자가 직접 구성해야 했지만, AgentCore runtime은 동일한 에이전트 로직을 그대로 감싸는 데코레이터 패턴으로 이런 운영 요소를 자동 처리한다는 점이 다르다.

★01Apple, 'DSAS' 공개 — 필요한 입력에만 강도 조절해 활성화 스티어링 성능 저하 방지Dynamically Scaled Activation Steering✍️ 블로그 · machinelearning.apple.com기존 활성화 스티어링(activation steering)은 모든 입력에 동일한 강도로 개입해 스티어링이 필요 없는 경우에도 모델 성능을 떨어뜨리는 문제가 있었다.

Apple은 이를 해결하기 위해 Dynamically Scaled Activation Steering(DSAS)를 제안한다. DSAS는 스티어링을 언제 적용할지와 어떻게 적용할지를 분리해, 레이어와 입력별로 개입 강도를 적응적으로 조절한다. 원치 않는 행동이 감지될 때만 강하게 개입하는 방식으로, 기존 스티어링 기법에 방법 독립적으로 적용 가능하다.

WHY IT MATTERS

독성 완화 등 생성 모델의 행동 제어 기법이 필요할 때만 개입하도록 정교화되면, 안전성 개선과 기존 성능 유지를 동시에 달성할 수 있다.

WHAT'S DIFFERENT

모든 입력에 균일하게 개입하는 기존 활성화 스티어링 방법들 대비, DSAS는 입력·레이어별로 개입 강도를 동적으로 조절해 불필요한 개입으로 인한 성능 저하를 줄인다.

WHY IT MATTERS

CFD처럼 데이터 생성 비용이 큰 분야에서 사전학습이 항상 이득이라고 단정할 수 없으며, 데이터 규모와 물리 모델 차이에 따라 효과가 역전될 수 있음을 보여준다는 점에서 서로게이트 모델 설계자에게 실질적 지침이 된다.

WHAT'S DIFFERENT
