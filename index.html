★01AWS, Amazon OpenSearch Service에 MCP Apps 도입 — IDE 채팅창에서 트레이스·서비스맵 바로 검증Agentic observability with Amazon OpenSearch Service MCP Apps✍️ 블로그 · aws.amazon.com관측 에이전트는 로그와 트레이스를 빠르게 조회해 근본 원인 가설을 제시하지만, 사용자는 이를 검증하기 위해 별도 브라우저 탭을 열고 대시보드를 직접 탐색해야 했다.

Amazon OpenSearch Service의 MCP Apps는 Model Context Protocol을 확장해 도구 호출 응답에 텍스트 설명과 함께 트레이스 워터폴, 서비스 토폴로지 같은 인터랙티브 시각화를 IDE 채팅창 안에 함께 렌더링한다. 시각화는 대시보드와 동일한 데이터 소스에 대해 코드를 실행해 생성되므로 AI의 해석이 아닌 결정론적 쿼리 결과를 그대로 보여준다. 로컬 MCP 서버가 에이전틱 IDE와 OpenSearch UI 애플리케이션 사이의 보안 브리지 역할을 하며 관측 도구들을 노출한다.

WHY IT MATTERS

에이전트가 답을 빠르게 내놓아도 사용자가 별도 도구로 옮겨가 수동 검증하는 과정이 병목이 되어 자동화의 속도 이점을 상쇄해왔는데, 이는 로컬 에이전틱 관측 체계를 운영하는 조직의 주된 부담이었다.

WHAT'S DIFFERENT

기존에는 에이전트의 텍스트 응답을 검증하려면 별도 관측 UI에 로그인해 쿼리를 재실행해야 했지만, MCP Apps는 동일한 대화 스레드 안에서 실제 대시보드와 같은 데이터 소스 기반의 결정론적 시각화를 함께 제공한다는 점이 다르다.

02The Interaction Tax: When Communication Erases Diversity in Multi-Agent Teams멀티에이전트 LLM, 서로의 답 그대로 공유하면 다양성 붕괴 — 11개 최적화 과제서 '독립 제안'이 더 우수📄 논문 · arxiv.org · ICML 2026이 논문은 멀티에이전트 LLM 상호작용이 성능을 높이는지 낮추는지에 대한 상반된 기존 연구 결과를 재검토한다.

저자들은 에이전트가 서로의 완전한 출력을 그대로 읽을 경우 한 라운드 만에 제안이 수렴해, 여러 모델을 쓰는 이유였던 다양성이 사라진다고 지적하며 이를 '상호작용 세금(interaction tax)'이라 명명한다. 동일 예산 조건에서 11개의 검증자 채점 최적화 과제로 실험한 결과, 전체 해답을 공유하는 상호작용은 약한 기본 전략이었고 독립적 제안 생성이 이 수렴 붕괴를 피했다. 전체 해답 공유는 에이전트가 처음 본 해답 근처에 머물게 만들 뿐이며, 비평(critique)은 위반 규칙을 LLM이 쉽게 찾아 고칠 수 있을 때만 도움이 되었다.

WHY IT MATTERS

디베이트, 비평 루프, mixture-of-agents 등 멀티에이전트 기법을 도입할 때 에이전트 수보다 어떤 정보를 언제 교환하는지가 성능을 좌우한다는 점을 보여준다.

WHAT'S DIFFERENT

기존의 디베이트(Du et al., 2024), 비평 루프(Chen et al., 2025), mixture-of-agents(Wang et al., 2025) 연구가 상호작용의 이점을 보고한 것과 달리, 이 논문은 전체 해답 공유형 상호작용이 오히려 다양성을 없애 성능을 해칠 수 있음을 보이고 독립 제안 생성을 대안으로 제시한다.

02TileMix: Tile-Centric Mixed-Precision Attention for LLM Inference AccelerationTileMix, 타일 단위 혼합정밀도 어텐션으로 LLM 프리필 가속 — INT8 정확도 손실 복구하며 FP16 대비 처리량 향상📄 논문 · arxiv.orgTileMix는 긴 문맥 프리필에서 발생하는 밀집 셀프어텐션의 연산·메모리 부담을 줄이기 위해, 어텐션 행렬을 하드웨어에 맞춘 스코어 타일로 나누고 각 타일 그룹의 정밀도(FP16 또는 INT8)를 라우팅하는 커널이다.

라우팅 결정은 비트마스크로 압축되며, 두 정밀도 경로 모두 공유된 온라인 소프트맥스 상태를 갱신한다. 인접 키 타일들을 하나의 라우팅 비트로 묶는 확장 가능한 정밀도 그룹핑을 통해 긴 문맥에서도 하드웨어 정합 연산 타일과 압축된 메타데이터를 유지한다. 훈련 없이 모든 유효 타일 그룹을 라우팅해 밀집 토큰 연결성을 보존하며, GQA·가변 길이 배치·INT8 KV 캐시를 지원한다. LongEval, LV-Eval, A100 프리필 벤치마크에서 LLaMA, Qwen, Vicuna 모델에 대해 균일 INT8 대비 손실된 장문 품질을 회복하면서 FP16 대비 프리필 처리량을 향상시켰다.

WHY IT MATTERS

긴 문맥 LLM 서비스에서 정밀도-효율 트레이드오프를 모델별로 조절 가능한 프론티어로 제시해, 배포 환경에 맞춰 정확도와 속도를 유연하게 선택할 수 있게 한다.

WHAT'S DIFFERENT

기존의 균일 저정밀도 경로나 토큰 상호작용 선택 방식과 달리, 하드웨어 정합 스코어 타일 단위로 공간적 정밀도 라우팅을 밀집 어텐션 커널 내부에 통합한 점이 다르다.

WHAT'S DIFFERENT

01Tabular foundation models for non-tabular tasks표 형태 데이터 없이도? TabPFN v3, MNIST·언어식별·Tiny ImageNet서 미세조정 없이 준수한 정확도📄 논문 · arxiv.org이 논문은 표 형태(tabular) 데이터를 위해 만들어진 사전학습 모델 TabPFN v3가 원래 표 데이터가 아닌 과제에도 적용될 수 있는지 검증한다.

MNIST 손글씨 인식, 프랑스어·독일어 단어의 언어 식별, Tiny ImageNet 이미지 분류라는 세 가지 비표형 분류 문제를 각각 테이블의 행으로 표현하고, 누락된 레이블 예측 문제로 재구성했다. 별도의 추가 학습이나 파인튜닝 없이 컨텍스트로 제공되는 샘플 수에 따른 성능을 측정했다. 이미지의 공간 구조나 텍스트의 순차 구조에 대한 명시적 접근 없이도, TabPFN v3는 일부 경우 해당 과제에 특화된 모델과 비교 가능한 정확도를 보였다.

WHY IT MATTERS

표 데이터 전용으로 설계된 파운데이션 모델이 구조적 정보 없이도 이미지·텍스트 과제에 통할 수 있다면, 데이터 표현 방식에 얽매이지 않는 범용 소수샷 학습 도구로서의 잠재력을 시사한다.

WHAT'S DIFFERENT

이미지의 공간 구조나 텍스트의 순차 구조를 활용하는 CNN이나 시퀀스 모델과 달리, TabPFN v3는 이런 구조 정보를 전혀 사용하지 않고 단순히 테이블 형태로 변환된 데이터만으로 추론과 유사한 성능을 낸다는 점이 다르다.
