AI 에이전트 — 자율 실행·툴 사용·멀티에이전트 협업
★01Axonius, Bedrock AgentCore로 멀티테넌트 AI 에이전트 구축 — 실로(silo) 모델로 테넌트별 격리·비용추적 구현How Axonius built secure multi-tenant AI agents on Bedrock AgentCore✍️ 블로그 · aws.amazon.comAxonius는 1,400개 이상 시스템 데이터를 통합해 보안 리스크를 분석하는 자산 인텔리전스 플랫폼으로, AWS 상에서 고객별 격리된 VPC를 사용하는 실로(silo) SaaS 아키텍처를 운영해왔다.

새로 도입한 AI 에이전트는 대규모 엔터프라이즈 환경의 상태를 해석해 리스크와 격차를 식별하며, 이를 통해 주니어 분석가도 시니어 분석가의 수작업 없이 복잡한 분석을 수행할 수 있게 됐다. Axonius는 기존 실로 기반 테넌트 관리 방식을 유지하면서 Amazon Bedrock AgentCore를 도입했고, 테넌트 격리, 아이덴티티 연동, 테넌트별 모델 비용 추적을 핵심 요구사항으로 설정했다. 이 글은 ISV가 선택할 수 있는 실로·풀·브리지 세 가지 멀티테넌시 패턴을 소개하고 AgentCore가 이를 어떻게 지원하는지 설명한다.

WHY IT MATTERS

여러 고객사의 민감 데이터를 다루는 SaaS 사업자에게는 에이전트 단위의 테넌트 격리와 비용 통제가 서비스 신뢰성과 수익성을 좌우하는 핵심 과제다.

WHAT'S DIFFERENT

기존의 단일 테넌트 공유형 에이전트 운영과 달리, Axonius는 AgentCore 런타임에서 테넌트별 전용 에이전트를 배포하는 실로 모델을 유지하며 기존 인증 모듈과 통합했다는 점이 다르다.

Coinbase와 Stripe Privy 지갑을 연동해 에이전트가 유료 API, MCP, 콘텐츠 비용을 몇 줄의 코드로 자율 결제할 수 있게 한다. GA 버전에서는 x402 프로토콜 외에 Stripe와 Tempo가 공동 개발한 Machine Payment Protocol(MPP)을 추가 지원하며, x402의 'upto' 스킴으로 고정가 대신 사용량 기반 지출 상한 설정이 가능해졌다. 개발자 자격증명은 AgentCore Identity Secrets Manager에 저장되고 에이전트는 원시 자격증명을 볼 수 없으며, 결제는 단일 에이전트 상호작용 단위의 '결제 세션' 내에서 실행된다.

WHY IT MATTERS

에이전트가 도구를 스스로 조합해 작업을 완수하는 수준까지 왔지만 결제 단계에서 막히는 문제를 해결한 것으로, 자율 마이크로결제 인프라가 표준화되면 에이전트 경제 전반의 상거래 방식이 바뀔 수 있다.

WHAT'S DIFFERENT

프리뷰 당시 x402 프로토콜만 지원했던 것과 달리, GA에서는 MPP 프로토콜과 'upto' 지출 상한 스킴을 추가해 고정가 결제 방식이었던 기존 'exact' 스킴의 한계를 넘어 사용량 기반 동적 과금을 지원한다.

01Apple, GRPO 다국어 실험 — 모국어로 추론 학습해도 영어 학습 대비 성능 격차 미미GRPO Beyond English: A Large-Scale Study of GRPO in Non-English and Multilingual Settings✍️ 블로그 · machinelearning.apple.comApple 연구팀이 RLVR와 GRPO를 활용한 추론 능력 강화 학습을 영어 중심을 벗어나 다국어·비영어 환경에서 대규모로 실증 분석했다.

다양한 베이스 모델, 학습 언어, 추론 언어 보상 조합에 걸쳐 실험을 진행했다. 그 결과 모델이 모국어(native language)로 추론하도록 학습해도 영어로 추론하도록 학습한 경우와 비교해 성능 격차가 크지 않음을 발견했다. 또한 강력한 추가 경향성도 관찰되었다고 언급하나 구체적 내용은 이어지지 않는다.

WHY IT MATTERS

기존 RLVR·GRPO 연구가 영어 중심으로 편중되어 있던 상황에서, 다국어 추론 학습의 실효성을 대규모로 검증했다는 점에서 비영어권 LLM 개발 방향에 실질적 근거를 제공한다.

WHAT'S DIFFERENT

기존 GRPO 연구들이 대부분 영어 중심 설정에 국한되었던 것과 달리, 이 연구는 다양한 언어와 보상 조합을 아우르는 대규모 다국어 실증 분석을 수행했다는 점이 다르다.

02AWS, AIDA 공개 — Amazon Bedrock 지식베이스에 암묵·명시적 필터링 적용해 계약서 RAG 검색 정확도 개선Improve contract search accuracy with auto-generated filters in Amazon Bedrock✍️ 블로그 · aws.amazon.comAIDA는 AWS 기반 솔루션으로 방대한 계약서를 검색 가능한 형태로 변환해 자연어 질의를 지원한다.

단순 시맨틱 검색만으로는 법률 문서의 맥락을 충분히 반영하지 못해 중요한 조항이 누락되거나 잘못 해석될 위험이 있다는 문제의식에서 출발했다. 이를 해결하기 위해 Amazon Bedrock Knowledge Bases의 메타데이터 기반 청킹과 암묵적·명시적 필터링을 결합해 검색 정확도를 높였다. 계약서는 당사자, 발효일, 종료일, 관할권 등 구조화된 메타데이터와 함께 수집되며, 이 메타데이터가 청크 분할과 필터링 단계에서 핵심 역할을 한다. 문서 청크는 벡터 임베딩으로 변환되어 Amazon OpenSearch Service나 Amazon S3 Vectors 같은 벡터 데이터베이스에 저장되고, IAM 기반 접근 제어와 CloudWatch 감사 로깅으로 보안과 규정 준수를 관리한다.

WHY IT MATTERS

엔터테인먼트·미디어처럼 수천 건의 계약서를 여러 관할권에서 다뤄야 하는 산업에서는 수작업 계약 검토가 비용과 시간 면에서 확장성의 병목이 되는데, RAG 기반 자동화가 이를 완화할 잠재력을 보여준다. 특히 법률 문서처럼 맥락 의존도가 높은 도메인에서 RAG 검색 정확도를 높이는 실전 아키텍처 사례로서 참고 가치가 크다.

WHAT'S DIFFERENT

기존의 표준 RAG 구현이 시맨틱 검색만으로 관련 청크를 찾는 것과 달리, AIDA는 메타데이터 기반 암묵적 필터링을 추가해 문서 수준 맥락과 접근 권한 경계를 함께 고려한다는 점에서 차별화된다.

01NVIDIA, 멀티 GPU로 UMAP 대규모 데이터 처리 — 정확도 유지하며 수 분 내 완료Run Massive-Scale UMAP in Minutes Using Multiple GPUs—Without Losing Accuracy✍️ 블로그 · developer.nvidia.comUMAP은 시각화와 특징 추출에 널리 쓰이는 차원 축소 기법으로, 탐색적 데이터 분석·토픽 모델링·단일세포 분석 등에 활용된다.

이런 워크플로는 반복적·탐색적이어서 파라미터를 조정할 때마다 UMAP을 여러 번 실행해야 한다. 데이터셋 규모가 커지면서 이 반복 실행에 걸리는 시간이 병목이 되는 문제가 있다. NVIDIA는 여러 GPU를 활용해 대규모 UMAP 연산을 수 분 내에 처리하는 방법을 소개한다.

WHY IT MATTERS

대규모 데이터셋에서 UMAP을 반복 실행해야 하는 탐색적 분석·단일세포 분석 워크플로의 속도 병목을 해소할 수 있어, 데이터 탐색과 파라미터 튜닝 주기를 크게 단축할 수 있다.

WHAT'S DIFFERENT

기존 단일 GPU 또는 CPU 기반 UMAP 실행 대비 멀티 GPU 확장을 통해 정확도 손실 없이 대규모 데이터를 더 빠르게 처리한다는 점이 다르다.

★01Localized TabICLv2: Scaling Tabular In-Context Learning through k-NNLocalized TabICLv2, k-NN으로 표 데이터 ICL 가속 — 정확도 98.64% 유지하며 단일 쿼리 최대 249배 속도 향상📄 논문 · arxiv.org · ICMLTabICLv2는 표 데이터 분류에서 최고 성능을 보이지만, 전체 학습 컨텍스트를 사용하는 attention 방식 때문에 데이터셋이 커질수록 추론 비용이 급증하는 문제가 있다.

Localized TabICLv2는 테스트 포인트마다 전체 학습 데이터 대신 모델의 Stage 2 행 표현 공간에서 유사도가 가장 높은 k개의 최근접 이웃만 검색해 컨텍스트로 사용한다. 아키텍처 변경 없이 적용 가능하며, 추가적인 Stage 2·Stage 3 파인튜닝을 통해 정확도 손실을 줄일 수 있다. TabArena 분류 과제에서 파인튜닝된 localized 모델은 Full TabICLv2 정확도의 98.64%를 유지하면서 배치 추론에서 중앙값 2.18배, 단일 쿼리 서빙에서는 약 249배의 속도 향상을 달성했다.

WHY IT MATTERS

표 데이터 기초 모델의 실용적 배포 걸림돌인 대규모 컨텍스트 attention 비용을 정확도 손실 없이 완화할 수 있다는 점에서, 대용량 데이터셋에 ICL 기반 표 모델을 적용하려는 실무자에게 중요하다.

WHAT'S DIFFERENT

기존 Full TabICLv2가 전체 학습 컨텍스트를 attention에 사용하는 것과 달리, k-NN 검색으로 컨텍스트를 국소화해 아키텍처 변경 없이 추론 비용을 줄인다.

WHY IT MATTERS

WHAT'S DIFFERENT

핵심은 각 액션 이벤트를 상품, 상호작용, 서피스 등 여러 필드 토큰으로 분해하는 필드별 토큰화 스킴으로, 이를 통해 필드 수준 어텐션과 필드별 학습 목표를 사용할 수 있다. 손실 함수 구성, 토큰화 세분도, 학습 데이터 범위에 대한 오프라인 ablation을 통해 각 설계 선택의 기여도를 분리 분석했다. SAGA 임베딩을 통합한 다운스트림 모델은 다양한 터치포인트에서 비교 대상 아키텍처들 대비 가장 높은 클릭·전환 개선을 보였다.

WHY IT MATTERS

단일 서피스 행동만 다루던 기존 추천 임베딩의 한계를 넘어, 실제 기업 환경에서 흔한 이종 도메인 행동 데이터를 통합 활용하는 실전 사례를 제시한다는 점에서 산업 적용 가치가 크다.

WHAT'S DIFFERENT

단일 토큰으로 액션을 융합하던 기존 접근과 달리, 이벤트를 여러 필드 토큰으로 분해해 필드 수준 어텐션과 학습 목표를 지원하는 점이 차별점이다.

02Sequential Multimodal Evidence Optimization for Product Media Ranking in E-Commerce이커머스 상품 미디어 정렬 SMEO — 전환율 5.5%↑, 구매까지 스와이프 15%↓📄 논문 · arxiv.org · CIKM 2026SMEO는 이미지·동영상·3D 렌더 등 이질적 상품 미디어를 고객이 순차적으로 소비할 때, 클릭이나 체류시간 같은 단기 지표 대신 구매 의사결정에 실제로 도움이 되는 순서를 학습하는 2단계 프레임워크다.

1단계에서는 로그 데이터의 위치 편향과 소비 깊이 불균형을 보정하면서, 소비된 미디어 접두 시퀀스로부터 궤적 효용 모델을 학습해 순서화된 증거가 구매 결정에 얼마나 기여하는지 추정한다. 2단계에서는 생존 가중 reward-to-go를 사용한 자기회귀 정렬 정책을 학습시켜, 제한된 고객 주의력을 고려해 의사결정에 가장 중요한 정보를 앞쪽에 배치한다. 효용 학습과 정책 최적화를 분리함으로써 편향된 로그로부터 안정적인 오프라인 학습과 미디어 단위 라벨 없이도 사후 귀속(attribution)이 가능하다. 대규모 이커머스 세션에서 이중강건(doubly robust) 오프폴리시 추정으로 평가한 결과, 전환율 5.5% 개선과 구매 결정까지 스와이프 15% 감소를 달성했다.

WHY IT MATTERS

클릭·체류시간 같은 근시안적 대리지표 대신 구매 여정 전체의 효용을 최적화하는 접근은 실제 매출과 고객 경험에 직결되는 랭킹 문제 설계 방식을 재고하게 만든다.

WHAT'S DIFFERENT

클릭·체류시간을 최적화하는 기존 미디어 랭킹 시스템 대비, 궤적 효용 모델과 생존 가중 강화학습 정책을 분리해 편향된 로그에서도 안정적으로 학습하고 미디어별 라벨 없이 귀속을 수행한다는 점이 다르다.
