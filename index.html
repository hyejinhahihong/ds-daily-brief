★01"RAG는 기억하지 않는다" — 추측 대신 지식 축적하는 영속 지식 레이어 설계, Azure로 구현Designing a Persistent Knowledge Layer That Refuses to Guess✍️ 블로그 · towardsdatascience.com이 글은 RAG(검색 증강 생성)가 매번 검색만 할 뿐 이해를 축적하지 못한다는 한계를 지적하고, 애플리케이션이 지식을 지속적으로 쌓아가는 영속 지식 레이어를 설계하는 벤더 중립적 청사진을 제시한다.

Microsoft Foundry, Azure AI Search, Cosmos DB, FastAPI를 활용한 Azure 네이티브 구현 예시를 제공하며, 이를 부동산 보험(property-insurance) 데이터에 적용한 사례를 다룬다.

WHY IT MATTERS

단순 검색-생성 파이프라인을 넘어 시스템이 답을 추측하지 않고 축적된 지식에 근거해 응답하도록 만드는 설계는 신뢰성 높은 엔터프라이즈 AI 애플리케이션 구축에 실용적 참고가 된다.

WHAT'S DIFFERENT

기존 RAG가 매 질의마다 문서를 재검색하는 방식인 반면, 이 접근은 검색 결과를 누적·유지하는 지식 레이어를 별도로 두어 시스템이 점진적으로 이해를 쌓아가도록 한다는 점이 다르다.

02에이전틱 AI 확산에 CPU 수요 폭증 — AWS "CPU 사이클 아껴라" 지침, 인텔·AMD도 병목 확인The CPU Comeback Is Upon Us📰 뉴스 · spectrum.ieee.orgAWS는 AI 워크로드로 인한 CPU 서버 대기시간 급증에 대응해 엔지니어들에게 CPU 사이클 절약을 지시했다.

그동안 GPU와 메모리가 AI 붐의 중심이었지만, 자율적으로 하위 에이전트를 호출하는 에이전틱 AI 확산으로 2026년 들어 CPU 수요가 급증했다는 분석이다. 인텔과 AMD 연구진에 따르면 도구 호출, API 실행, 결과 취합 같은 에이전틱 작업 단계는 대부분 CPU에서 처리되며, AMD 테스트에서는 에이전틱 파이프라인 8단계 중 7단계가 전적으로 CPU에서 실행된다. 인텔 연구팀은 GPU 추론 중 CPU가, CPU 도구 호출 중 GPU가 유휴 상태가 되는 비효율을 발견하고 스케줄링 최적화로 지속 부하 시 지연시간을 최대 1.8배 줄이는 방안을 제시했다.

WHY IT MATTERS

GPU 중심으로 짜인 AI 인프라 투자 전략이 에이전틱 AI 확산에 따라 CPU 병목이라는 새로운 제약에 부딪히고 있어, 클라우드·데이터센터 설계 전반의 재점검이 필요함을 시사한다.

WHAT'S DIFFERENT

기존에는 LLM 추론이 GPU 병목의 핵심으로 여겨졌던 것과 달리, 이번 사례들은 도구 호출·안전 가드레일 처리 등 에이전틱 워크로드의 상당 부분이 CPU에서 실행되며 GPU와 CPU가 서로 번갈아 유휴 상태에 놓이는 새로운 비효율 패턴을 지적한다.
