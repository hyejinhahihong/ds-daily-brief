01NVIDIA, cuTile로 Mamba-2 순전파 커널 가속 — Python DSL로 타일 단위 GPU 프로그래밍 자동 최적화Accelerating Mamba-2 with High-Performance Forward Pass Kernels in NVIDIA CUDA Tile✍️ 블로그 · developer.nvidia.comNVIDIA CUDA Tile(cuTile)은 NVIDIA GPU용 Python 기반 DSL이자 병렬 프로그래밍 모델이다.

스레드·워프 수준의 스케줄링을 타일 중심의 고수준 primitive로 추상화해, 사용자는 Python으로 GPU 커널을 작성하고 컴파일러가 자동으로 하드웨어 성능을 최적화하도록 한다. 이 글은 cuTile을 활용해 Mamba-2의 순전파(forward pass) 커널을 고성능으로 구현하는 방법을 다룬다.

WHY IT MATTERS

저수준 CUDA 커널 작성 없이 Python만으로 고성능 GPU 커널을 만들 수 있다면, Mamba류 구조적 상태공간 모델(SSM) 같은 최신 아키텍처의 실험·배포 진입장벽이 크게 낮아진다.

WHAT'S DIFFERENT

기존 CUDA C++ 수준의 스레드·워프 스케줄링 관리 대비, cuTile은 타일 단위 primitive로 이를 추상화하고 컴파일러가 최적화를 자동 수행한다는 점이 다르다.

02MOSS-Image Technical ReportMOSS-Image 공개 — 5B DiT로 밀도 높은 텍스트·레이아웃 이미지 생성, LLTB 텍스트 커버리지 96.3%📄 논문 · arxiv.orgMOSS-Image는 고밀도 텍스트와 복잡한 레이아웃 생성에 취약한 오픈 가중치 텍스트-이미지 모델의 한계를 보완하기 위해 제안된 오픈 생성 시스템이다.

처음부터 사전학습한 5B 단일 스트림 확산 트랜스포머(DiT)를 통해 이중언어 장문 텍스트 렌더링과 정밀 레이아웃 제어를 지원하며, 사용자 요청을 세부 콘텐츠·레이아웃 명세로 변환하는 의도 인식 에이전트형 프롬프트 강화(PE) 모듈을 결합했다. 장문 텍스트 렌더링 평가용 LongLongTextBench(LLTB)와 레이아웃 중심 생성 평가용 RealLayoutArena(RLA)라는 두 벤치마크도 함께 제안했다. LLTB에서 오픈 가중치 모델 중 최고 성능으로 평균 텍스트 커버리지 96.3%를 달성했고, RLA에서는 엔드투엔드 비교 2위, 동일 강화 프롬프트 기준 생성기 자체 성능은 1위를 기록했다. 모델, 학습 레시피, 평가 프레임워크를 모두 공개할 예정이다.

WHY IT MATTERS

텍스트가 밀집된 그래픽이나 복잡한 레이아웃 생성은 폐쇄형 모델이 독점하던 영역이었는데, 이를 오픈 가중치로 재현 가능하게 한다는 점에서 텍스트-이미지 생성 생태계 전반에 영향을 줄 수 있다. 모델과 평가 프레임워크를 함께 공개함으로써 재현 연구와 후속 벤치마킹이 용이해진다는 점도 주목할 만하다.

WHAT'S DIFFERENT

기존 오픈 가중치 텍스트-이미지 모델들이 밀도 높은 텍스트·정교한 레이아웃 처리에서 어려움을 겪던 것과 달리, MOSS-Image는 처음부터 설계된 5B DiT와 의도 인식 프롬프트 강화 모듈을 결합해 이 격차를 좁혔다.

02Relational Learning as World ModelingTabWM, 관계형 세계모델 제시 — 실행 64회 관찰만으로 edit F1 0.016→0.685 상승📄 논문 · arxiv.org이 논문은 관계형 학습을 데이터베이스 상태 예측에서 '행동에 따른 상태 변화 예측'으로 확장한다.

저자들은 각 운영 시스템을 관계형 '월드'로 보고, 사전학습용 실행 가능 관계형 월드 생성기 WorldRel과 이를 활용하는 TabWM(Tabular World Model)을 제안한다. TabWM은 미지의 월드에서 관찰된 실행들을 맥락으로 삼아 파라미터 업데이트 없이 새로운 행동이 유발하는 희소 구조적 edit을 예측한다. 512개의 held-out 월드에서 실행 관찰 0회일 때 edit F1 0.016이던 것이 64회 관찰 시 0.685로 상승했으며, 정답 edit은 연산·관계형 위치·값이 모두 일치해야 한다. 예측된 edit은 재귀적으로 적용해 미래 상태를 상상하고 행동을 비교하는 데 쓰이며, 이를 통한 탐색 확장은 선택된 행동열의 실현 보상을 향상시킨다.

WHY IT MATTERS

관계형 데이터 기반 의사결정 시스템에서 '행동이 상태를 어떻게 바꾸는가'를 맥락 학습만으로 예측할 수 있다면, 시스템별 동역학을 몰라도 행동 계획과 시뮬레이션이 가능해진다는 점에서 의미가 크다.

WHAT'S DIFFERENT

기존 관계형 학습이 데이터베이스 상태 자체를 예측하는 데 그쳤던 것과 달리, TabWM은 파라미터 업데이트 없이 관찰된 실행만으로 행동에 따른 구조적 edit을 추론해 미래 상태를 재귀적으로 시뮬레이션한다는 점이 다르다.

연구진은 영어, 프랑스어, 그리스어로 작성된 90개 발행사의 2025회계연도 공시를 공통 회계 분류체계로 정렬하고, 사실 단위로 추적 가능한 주석을 단 벤치마크 MULTIFINGROUND를 공개했다. 이 벤치마크는 재무 사실 식별, 개념 인식, 후보 라벨 없는 완전한 사실 선택 및 개념 구분 능력을 평가한다. 15개 모델 중 API·오픈웨이트 기준모델 8개는 97.3~99.4%의 개념 인식 정확도를 보였지만, 올바르게 인식된 그룹에서도 26.6~41.9%는 최소 하나의 목표 사실을 누락했다. 금융 특화 모델도 큰 개선을 보이지 않았으며, 개념 구분 능력에는 상당한 편차가 나타났다.

WHY IT MATTERS

개념을 정확히 인식하는 것과 그 증거를 빠짐없이 모으는 것은 별개의 능력임을 보여주며, 재무 분석 등 완전성이 중요한 업무에 LLM을 적용할 때 의미 인식만으로는 신뢰할 수 없다는 점을 시사한다.

WHAT'S DIFFERENT

기존 벤치마크들은 개념 인식이나 사실 추출 중 한 측면만 평가했던 것과 달리, MULTIFINGROUND는 동일한 다국어 맥락에서 인식과 증거 완전성을 함께 측정해 '인식-근거화 격차'를 드러낸다.

01AWS, vLLM용 push 기반 KV 캐시 전송 공개 — EFA 환경 Qwen3-32B TTFT 최대 3배 개선Push-based KV transfer to improve TTFT and TPOT for disaggregated inference in vLLM✍️ 블로그 · aws.amazon.comvLLM의 prefill-decode 분리 추론에서 기존 NIXL 커넥터는 pull 방식으로 KV 캐시를 전송해 라우터 중계, 목적지 블록 할당, NIXL READ 요청이 순차적으로 발생해 TTFT 경로를 늘렸다.

AWS는 이 전송 조정·준비 과정을 critical path에서 분리한 push 기반 NIXL 커넥터를 소개한다. decode 인스턴스가 미리 목적지 블록을 등록해 두고, prefill 측이 백그라운드 스레드에서 전송 설정과 제출을 처리해 생산자·소비자 작업을 중첩시킨다. AWS Trainium 클러스터에서 개발·검증 후 가속기에 구애받지 않는 기능으로 vLLM에 기여했다. EFA로 연결된 EC2 P5en 1P1D 구성에서 Qwen3-32B 모델 기준 TTFT 최대 3배, TPOT 최대 30% 개선을 확인했다.

WHY IT MATTERS

분리형(prefill-decode) 추론 구조를 쓰는 대규모 LLM 서빙 환경에서 KV 캐시 전송 지연은 응답성의 핵심 병목이므로, 이를 줄이는 아키텍처 변화는 고부하 상황에서의 실사용 체감 성능에 직접 영향을 준다.

WHAT'S DIFFERENT

기존 pull 기반 NIXL 커넥터 대비, decode 측의 ID 탐색 왕복과 전송 준비 작업을 prefill 측 백그라운드 스레드로 옮겨 critical path에서 제거한 것이 핵심 차이다.

고객과의 대화에서 시작된 요청이 여러 팀을 거치며 원래 의미를 잃는 경우가 많았는데, 예컨대 '더 빠른 리포트'라는 표현이 화면 공유 맥락 없이는 '페이지 로딩 속도'와 '백엔드 처리 속도'로 서로 다르게 해석될 수 있었다. 기존 회의록 요약은 한 번의 회의만 다루고 화면 공유 중 가리킨 시각적 맥락을 놓치는 한계가 있었다. 이를 해결하기 위해 필자는 ContextCue라는 실험적 도구를 만들어, 녹화된 회의에서 음성 논의뿐 아니라 화면상의 시각적 맥락, 결정 사항과 그 근거, 출처까지 보존해 여러 팀에 걸쳐 이동 가능한 공유 컨텍스트를 생성하고자 했다.

WHY IT MATTERS

AI가 코딩 자체는 빠르게 만들었지만, 잘못 전달된 요구사항을 매우 효율적으로 '잘못 구현'하게 만들 위험이 있다는 점은 분산 팀 협업에서 AI 도입 전략을 재고하게 만든다.

WHAT'S DIFFERENT

기존 Microsoft Teams AI 요약 같은 도구는 단일 회의 단위로 텍스트 요약만 제공해 여러 회의에 걸친 맥락 축적과 화면 공유 중 시각적 의미를 놓치는 반면, ContextCue는 음성·시각 맥락·결정 근거·출처를 함께 보존해 팀 간 이동 가능한 컨텍스트로 만들고자 한다.

01Meta, GenRecs Tokenization 공개 — ID 대신 의미 토큰 어휘로 광고 추천, 전환율 +0.35% 상승GenRecs Tokenization: Transforming Ads Recommendation at Meta with Stable Model Vocabulary✍️ 블로그 · engineering.fb.comMeta는 광고마다 개별 ID를 부여하는 대신 안정적인 의미 토큰 어휘로 아이템을 표현하는 GenRecs Tokenization을 도입했다.

이는 모든 광고 후보를 개별 스코어링하던 기존 방식 대신 LLM 구조로 광고 콘텐츠와 사용자 선호를 함께 추론하는 GenRecs 패러다임의 기반 데이터 표현이다. 토큰은 아이템이 무엇을 나타내는지 설명하므로, 과거 참여 이력이 전혀 없는 신규 제품이나 광고도 모델이 이미 학습한 유사 카테고리의 지식을 상속받아 추론할 수 있다. Meta의 Generative Ads Model(GEM)과 Adaptive Ranking Model과 결합해 전 서비스 표면에서 전환율 +0.35% 상승을 달성했다. 이 어휘는 광고, 제품, 페이지, 픽셀 등 모든 아이템 유형에 걸쳐 검색(retrieval)과 랭킹(ranking) 양쪽에 적용된다.

WHY IT MATTERS

신규 엔티티에 대한 콜드스타트 문제를 의미 토큰으로 해결하면서 캠페인 간 통찰 전이와 LLM 스케일링 이득까지 함께 가져갈 수 있어, 산업 규모 추천 시스템 설계에 참고할 만한 사례다.

WHAT'S DIFFERENT

기존 추천 시스템이 아이템마다 고유 ID를 부여해 개별적으로 점수화하던 방식과 달리, 공유된 의미 토큰 어휘로 아이템을 표현해 참여 이력이 없는 신규 아이템도 유사 개념으로부터 지식을 전이받을 수 있다는 점이 다르다.
