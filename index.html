01NVIDIA, 하이브리드 모델용 ReplaySSM 공개 — SSM 상태 저장 방식 재설계로 디코딩 속도 개선ReplaySSM: Rethinking State Storage for Faster Hybrid-Model Decoding✍️ 블로그 · developer.nvidia.comReplaySSM은 SSM 레이어와 소수의 어텐션 레이어를 섞은 하이브리드 모델을 위한 상태 저장 기법이다.

NVIDIA Nemotron 3, Qwen3.5~3.8, Kimi-K3, GLM-5.3-Flash 등은 Mamba-2, Gated DeltaNet(GDN), Kimi Delta Attention(KDA) 같은 SSM 레이어를 사용해 디코딩을 빠르게 한다. SSM 레이어는 시퀀스 길이에 비례해 커지는 KV 캐시 대신 고정 크기 상태를 사용하도록 설계되어 있다. ReplaySSM은 이 고정 크기 상태의 저장 방식을 재고해 디코딩 효율을 높이는 접근을 다룬다.

WHY IT MATTERS

긴 시퀀스를 다루는 하이브리드 아키텍처가 확산되는 가운데, 상태 저장 방식 개선은 추론 비용과 지연 시간에 직접 영향을 미쳐 실제 서비스 배포에 중요하다.

WHAT'S DIFFERENT

기존 어텐션 기반 모델의 KV 캐시가 시퀀스 길이에 따라 선형적으로 증가하는 것과 달리, SSM 레이어는 고정 크기 상태를 사용하며 ReplaySSM은 이 상태 저장 방식 자체를 재설계한다.

02Amazon, 'Priming' 공개 — 사전학습 Transformer 재활용해 하이브리드 아키텍처 학습비용 99% 절감Can we change an AI model&#8217;s architecture without retraining it from scratch?✍️ 블로그 · amazon.scienceAmazon Web Services 팀이 사전학습된 Transformer 가중치를 출발점으로 삼아 하이브리드 상태공간 모델(SSM)을 만드는 Priming 기법을 제안했다.

이를 통해 하이브리드 아키텍처의 사전학습 비용을 99% 이상 줄여, 어떤 어텐션 레이어를 어떤 SSM으로 교체할지 대규모로 실험할 수 있게 됐다. Gated KalmaNet, Gated DeltaNet, Mamba-2 세 가지 SSM을 비교한 결과 Gated KalmaNet이 가장 우수했고, SSM들은 동일 품질에서 슬라이딩 윈도우 어텐션보다 2배 높은 처리량을 보였다. 320억 파라미터 GKA 기반 하이브리드 모델은 원본 Transformer와 동등한 추론 성능을 유지하면서 12만8천 토큰 컨텍스트에서 최대 2배 빠르게 디코딩하고, 정답 도달 시간을 3분의 2까지 단축했다.

WHY IT MATTERS

에이전트형 AI가 길어진 세션과 깊은 추론 체인을 다루면서 Transformer의 메모리 비용이 커지는 문제가 심화되는데, 이를 해결할 하이브리드 아키텍처 탐색을 대규모 재학습 없이 저비용으로 가능하게 한다는 점이 중요하다.

WHAT'S DIFFERENT

기존에는 새로운 하이브리드 아키텍처마다 수조 토큰과 수십만 GPU-시간을 들여 처음부터 재학습해야 했지만, Priming은 사전학습된 Transformer 가중치를 재사용함으로써 이 비용을 99% 이상 줄였다는 점이 다르다.

03MS, 학생 시뮬레이터 StudentSim 공개 — 체스·영작문·수학서 기존 AI 튜터 베이스라인 능가Simulating student learning for better AI tutoring✍️ 블로그 · microsoft.comStudentSim은 공개된 비식별 학습자 기록을 바탕으로 개별 학생을 모사하는 AI 시뮬레이터로, AI 튜터를 실제 학습자 대상 테스트 전에 연구 단계에서 평가·개선하기 위한 시스템이다.

각 시뮬레이터는 특정 학생처럼 응답하는지, 그리고 튜터의 안내 이후 답변이 실제로 업데이트되는지라는 두 가지 교육학적 기준으로 평가된다. 체스, 제2언어로서의 영어 글쓰기, 수학 세 영역에 걸쳐 StudentSim은 기존 베이스라인을 능가했으며, AI 튜터 학습에 유용한 피드백 신호를 제공했다. 이와 함께 StudentSimEval이라는 벤치마크 및 평가 프로토콜도 함께 공개됐다.

WHY IT MATTERS

실제 학습자를 대상으로 한 피드백 수집은 느리고 비용이 많이 들어 AI 튜터의 빠른 모델 반복 개선을 어렵게 만드는데, 시뮬레이션 기반 피드백은 이를 연구 단계에서 보완할 수 있는 수단이 된다.

WHAT'S DIFFERENT

단순히 LLM에 '수학을 어려워하는 초등학생' 역할을 맡기는 방식은 말투는 흉내 내지만 실제 학습자의 능력 한계를 벗어난 과도하게 유능한 답변을 내놓아 튜터 평가를 왜곡시키는 반면, 또한 기존 지식 추적(knowledge tracing) 모델은 실제 학습 기록에 기반하지만 자연어 형태의 튜터 안내를 입력으로 받아 반응을 예측하도록 설계되지 않았다는 한계가 있다.

01ARCS: Towards Precise Text-to-SQL via Structured DisambiguationARCS 벤치마크 공개 — 모호한 질문 포함 Text-to-SQL, gpt-6-sol도 정확도 51%에 그쳐📄 논문 · arxiv.org텍스트-투-SQL 시스템이 실제 환경에 배포될수록 사용자 질문의 모호성이 주요 오류 원인이 되고 있다.

기존에는 대화형 명확화로 이를 해결했지만 비효율적이고 사용자 워크플로우와 맞지 않는 문제가 있었다. 이 논문은 자유 대화 대신 명시적이고 제한된 상호작용으로 모호성을 해소하는 '구조화된 명확화' 패러다임을 제안한다. 실제 데이터베이스에서 자연 발생한 모호성을 모든 해석과 SQL 쿼리까지 완전히 주석 처리한 최초의 벤치마크 ARCS를 구축했다. 실험 결과 모호성이 있는 상황에서 gpt-6-sol도 실행 정확도 51%에 그쳤고, 오픈소스 모델은 모두 27%를 넘지 못했다.

WHY IT MATTERS

모호성 처리는 text-to-SQL의 실제 배포 성패를 가르는 핵심 요소인데, 최상위 모델조차 절반 수준의 정확도에 머문다는 점은 현 시스템의 한계를 명확히 보여준다.

WHAT'S DIFFERENT

기존의 대화형 명확화 방식 대신, 명시적이고 제약된 상호작용으로 모호성을 해소하는 구조화된 명확화 패러다임을 제시한 점이 다르다.

01uber/causalml v0.18.0 공개 — CausalTree에 honesty 기본 적용, uplift 트리 Cython 커널로 통합uber/causalml v0.18.0📦 릴리스 · github.comcausalml v0.18.0은 v1.0 전환을 앞두고 fit() 인자 순서를 변경하며 positional treatment/y 사용 시 FutureWarning을 발생시킨다.

CausalTreeRegressor와 CausalRandomForestRegressor는 기본값으로 honesty=True가 적용되어, 표본 절반으로 트리 구조를 만들고 나머지 절반으로 리프 값을 재추정한다. UpliftTreeClassifier와 UpliftRandomForestClassifier는 공유 Cython 트리 커널로 이전되어 결측값을 네이티브로 지원하며, 이름과 출력 형태는 유지된다. 이 외에 lalonde, ihdp, twins 등 벤치마크 데이터 로더와 pehe, ate_error, policy_risk 같은 ground-truth 평가 지표, 모델 save()/load(), 재구축된 문서 사이트가 추가됐다.

WHY IT MATTERS

causal forest 및 uplift 모델링 결과가 기본 동작 변경(honesty, propensity 모델 스코어 등)으로 달라질 수 있어, 기존 파이프라인의 재현성을 점검해야 한다.

WHAT'S DIFFERENT

기존 CausalTreeRegressor의 비honest 추정 방식 대비 Athey & Imbens(2016)의 honesty 기법을 기본값으로 채택했고, UpliftTree는 별도 구현 대신 causal tree와 동일한 Cython 커널을 공유하도록 통합됐다.

01Apple, 유휴 Apple Silicon GPU 모아 가상 GPU 클라우드 'Minions' 공개 — 대규모 추론 워크로드 분산 처리Minions: A Dynamic and Distributed Virtual GPU Cloud Built on Idle Apple Silicon Devices✍️ 블로그 · machinelearning.apple.comMinions는 macOS 기기에 탑재된 Apple Silicon GPU 중 평소 사용되지 않는 유휴 자원을 모아 대규모 머신러닝 추론 워크로드를 실행하는 동적 분산 가상 GPU 클라우드다.

기존 중앙집중형 GPU 인프라는 비용이 높고 탄력성이 부족하며 자원이 제한될 때 대기 시간이 길어지는 문제가 있다는 점에서 출발했다. Minions는 여러 macOS 기기에 흩어진 GPU를 집계해 팀이 기존 유휴 하드웨어를 활용할 수 있도록 지원한다.

WHY IT MATTERS

GPU 수급난 속에서 유휴 Apple Silicon GPU를 추론 인프라로 재활용할 수 있다면 중앙 GPU 클라우드 의존도를 낮추고 비용을 절감할 수 있다.

WHAT'S DIFFERENT

기존 중앙집중형 GPU 클라우드 대비, 이미 보유한 macOS 기기의 유휴 GPU를 분산 집계해 활용한다는 점이 다르다.

02AWS, llama.cpp로 SageMaker에 '결정 모델' 배포 — SemIf 어댑터로 옵션별 확률 반환Deploy decision models with llama.cpp on Amazon SageMaker AI✍️ 블로그 · aws.amazon.com이 글은 AWS DLC의 llama.cpp를 Amazon SageMaker AI에 배포해 라우팅, 에이전트 행동 선택, 정책 결과 할당 같은 작업에 필요한 '선택지 점수' 기반 결정 모델을 서빙하는 방법을 다룬다.

기본 경로는 OpenAI 호환 Chat Completions API로 텍스트를 생성하지만, SemIf(구 OpenJev)라는 확장 어댑터를 적용하면 답변 토큰을 디코딩하지 않고 정의된 옵션들에 대한 확률을 직접 반환한다. SemIf는 llama-server HTTP API가 노출하지 않는 최종 위치 로짓과 상태 연산을 활용하기 위해 AWS CodeBuild로 별도의 child 이미지를 빌드해 ECR에 저장한다. 요청은 caller가 정의한 ID, 비정형 상태, 질문, 허용 옵션 목록으로 구성되며, 응답은 option_ids, probabilities, raw option_logits를 순서대로 반환한다.

WHY IT MATTERS

자유형 텍스트 생성 대신 고정된 선택지에 대한 확률을 얻으면 애플리케이션이 생성된 문장을 파싱하지 않고도 임계값, 폴백, 정책 검증을 바로 적용할 수 있어 운영 신뢰성이 높아진다. CPU/GPU 양쪽에서 양자화 모델을 관리형으로 서빙할 수 있다는 점도 비용·지연 최적화 측면에서 실무적으로 유용하다.

WHAT'S DIFFERENT

기존 llama-server의 OpenAI 호환 채팅 완성 API 대비, SemIf는 답변 토큰 디코딩 없이 안정적인 옵션 ID와 확률·로짓을 직접 반환하는 제약된 결정 스키마를 사용한다는 점이 다르다.

01Meta, 유휴 추론 용량으로 광고 추천 고도화 — RMA·SBM 탄력성 레버로 베이스라인 성능 유지Turning Opportunistic AI Inference Capacity Into Better Ads Recommendations✍️ 블로그 · engineering.fb.comMeta는 유휴 상태의 추론 용량을 광고 추천 작업에 활용하는 시스템을 구축했다.

분산된 유휴 용량 조각들을 하나의 공유 기회 용량 풀로 모아 베이스라인 성능을 해치지 않으면서 추가 작업을 수행하게 한다. 핵심은 두 가지 탄력성 레버로, Rank More Ads(RMA)는 랭킹 단계에서 평가하는 후보 수를 늘리고, Serve Better Models(SBM)는 더 강력한 모델로 라우팅되는 요청 비율을 조정한다. 물리적·논리적 격리로 베이스라인 서빙용 용량을 보호하며, 용량이 갑자기 회수될 때 서버·클라이언트 양쪽에서 가치 기반 로드 셰딩으로 점진적으로 작업을 축소한다.

WHY IT MATTERS

추론 인프라는 전체적으로는 용량이 빠듯해도 지역·시간대·가속기 종류에 따라 국지적으로 유휴 자원이 남는 '용량 역설'을 겪는데, 이를 활용하면 추가 하드웨어 투자 없이 광고 추천 품질과 광고주 성과를 개선할 수 있다는 점에서 대규모 추론 인프라 운영 전반에 시사점이 크다.

WHAT'S DIFFERENT

기존의 고정된 팀별·리전별 용량 할당 방식과 달리, 유휴 용량을 공유 풀로 통합하고 RMA·SBM 두 레버와 로드 셰딩으로 안전하게 가변 활용한다는 점이 차별점이다.

02Clinician use of language models diverges from how the models are evaluated의료현장 LLM 사용 12만 쿼리 분석 — 기존 벤치마크, 실제 업무와 31%만 일치📄 논문 · arxiv.org8개월간 35개 전문분야 임상의 6,342명이 보낸 127,833건의 LLM 질의를 분석한 연구다.

연구진은 임상의 검증을 거친 RCQ-Map 프레임워크로 각 쿼리의 과제, 의도, 답변 가능성, 누락 정보, 잠재적 위해를 분류했다. 실제 사용의 36.2%는 문서화·행정 업무, 28.9%는 지식 검색이었고 진단은 3.7%에 불과했으며, 쿼리의 3분의 1 이상은 제대로 답변하기 어려운 형태였다. 58개 공개 벤치마크를 같은 방식으로 분석한 결과(Clinical AI Benchmark Atlas), 중간값 벤치마크는 문서화 요청을 전혀 포함하지 않았고 실제 업무와의 과제 구성 일치율은 31%에 그쳤다.

WHY IT MATTERS

임상 특화를 표방한 벤치마크 스위트조차 프런티어 모델 보고서용 벤치마크와 실제 업무 유사도에서 차이가 없어, 벤치마크 점수가 실제 임상 배치 성능을 예측하지 못할 수 있음을 시사한다.

WHAT'S DIFFERENT

기존 벤치마크들은 시험 문제나 선별된 사례 중심으로 구성되는데, 이 연구는 실제 127,833건의 현장 쿼리 분포와 비교해 벤치마크-실사용 간 괴리를 정량적으로 측정했다는 점이 다르다.
