01AWS, SageMaker AI에서 MoE 커널 최적화 — Swap-AB로 Hopper WGMMA 활용도 개선Mixture-of-Experts kernel engineering on Amazon SageMaker AI✍️ 블로그 · aws.amazon.com이 글은 Amazon SageMaker AI에서 Mixture-of-Experts(MoE) 모델의 연산 효율을 높이기 위한 커널 엔지니어링 기법을 다룬다.

Fused MoE는 토큰 라우팅, 데이터 셔플링, 전문가 연산을 GPU 상의 단일 배치 연산으로 통합해 지연시간을 줄이지만, 커널 구현과 디버깅 복잡도가 높아진다. NVIDIA Hopper 아키텍처의 WGMMA 명령어는 행렬 M 차원을 64로 고정하는 구조적 제약이 있어, 디코드 단계처럼 토큰 배치 크기가 1에 가깝게 작아지면(M<64) 텐서 코어 자원이 크게 낭비된다. 이를 해결하기 위해 Swap-AB 기법으로 오퍼랜드 배치를 조정해 WGMMA 활용도를 높이는 방법을 제시한다.

WHY IT MATTERS

MoE 아키텍처는 LLM 용량을 키우면서도 토큰당 연산량을 낮추지만, 디코드 단계의 작은 배치 크기가 하드웨어 활용도를 떨어뜨려 지연시간과 비용에 직접 영향을 준다. 이런 하드웨어 특화 커널 최적화는 MoE 서빙 효율을 좌우하는 실무적으로 중요한 요소다.

WHAT'S DIFFERENT

기존의 순차적 라우팅·전문가 연산 루프 방식 대비, Fused MoE는 이를 단일 배치 GPU 연산으로 통합하며, 여기에 Swap-AB를 적용해 Hopper WGMMA의 고정된 M=64 레이아웃 제약으로 인한 텐서 코어 유휴 문제를 완화한다.

02Apple 연구, 저자원 언어 사전학습서 하이퍼파라미터 튜닝보다 이중언어 데이터 혼합이 더 효과적Mix, Don't Tune: Bilingual Pre-Training Outperforms Hyperparameter Search in Data-Constrained Settings✍️ 블로그 · machinelearning.apple.com저자원 언어의 언어모델 사전학습은 데이터가 부족해 같은 데이터를 여러 번 반복 학습해야 하며, 이는 일반화 성능을 저하시킨다.

이를 해결하는 두 가지 방법으로 높은 weight decay 같은 공격적 하이퍼파라미터 튜닝과, 고자원 보조 언어 데이터를 섞는 방식이 있다. 하이퍼파라미터 튜닝은 가중치를 축소해 네트워크 용량을 제한하는 방식으로 규제하는 반면, 보조 데이터 혼합은 혼합 비율을 조절해 학습 분포를 확장하고 새로운 신호로 다양성을 높인다. 데이터 제약 환경에서는 이러한 보조 언어 혼합 방식이 하이퍼파라미터 탐색보다 우수한 성능을 보인다.

WHY IT MATTERS

세계 대부분의 언어는 사전학습 데이터가 부족한 상황에 놓여 있어, 이런 저자원 환경에서 효과적인 전략을 찾는 것은 다국어 모델 구축에 실질적인 영향을 미친다.

WHAT'S DIFFERENT

기존의 공격적 하이퍼파라미터 튜닝(높은 weight decay 등)을 통한 모델 용량 제한 방식 대비, 보조 언어 데이터를 섞어 학습 분포 자체를 확장하는 방식이 더 나은 성능을 보인다는 점에서 차별화된다.

03WOVEN: Weaving Visual World Modeling into Multimodal LLMsWOVEN 공개 — 시각 전이 추론 학습으로 MLLM 외부 벤치마크 26개 중 22개 최대 27.3%p 개선📄 논문 · arxiv.org연구진은 MLLM이 공간·신체화·물리·시간 추론에서 겪는 실패가 '시각 전이 추론'이라는 공통 결함에서 비롯된다고 가정하고, 이를 검증하기 위해 WOVEN이라는 학습 자원 겸 벤치마크를 제안했다.

WOVEN은 비디오 사전학습 생성 모델의 롤아웃을 활용해 20종 장면, 5종 행동, 8종 추론 유형으로 구성된 36,076개 예제를 포함한다. GPT-5.4, Qwen3-VL-235B-A22B 등 38개 최신 MLLM을 평가한 결과 모든 모델이 사람보다 크게 뒤처지는 결함을 보였고, 이는 모델군과 규모에 상관없이 반복됐다. WOVEN으로 여러 규모의 MLLM을 학습시키자 각 2,000개 정도의 부분집합만으로도 26개 외부 벤치마크 중 22개가 최대 27.3%p 개선됐으며, 기존 과제별 학습 데이터의 30~50%를 WOVEN 데이터로 대체해도 비슷한 정확도를 유지했다.

WHY IT MATTERS

여러 추론 과제에 공통으로 재사용 가능한 학습 프리미티브를 발견했다는 점에서, 과제별 데이터 수집 없이도 범용 시각 세계 모델링 능력을 효율적으로 끌어올릴 수 있는 길을 제시한다.

WHAT'S DIFFERENT

기존 벤치마크들이 장면·행동·추론 결함을 개별적으로만 기록해 비교가 어려웠던 것과 달리, WOVEN은 장면·행동·추론 유형을 통제된 축으로 조직화해 직접 비교가 가능하며, 행동이나 장면이 아니라 가르치려는 추론 연산 기준으로 감독 데이터를 선택해야 한다는 학습 레시피를 제시한다.

02AWS, Bedrock Private Pricing Offer 다중 계정 배포 자동화 — 스크립트·CDK 두 가지 경로 공개Manage private pricing offers for Amazon Bedrock with managed entitlements✍️ 블로그 · aws.amazon.comAmazon Bedrock에서 AWS Marketplace Private Pricing Offer(MPPO)를 사용할 때, 조직 내 각 워크로드 계정이 개별적으로 구독·수락해야 하는 번거로움을 managed entitlements로 해결한다.

조직 전체 기능이 활성화된 AWS Organizations에서는 조직 수준 grant가 자동 수락되지만 기본적으로 Disabled 상태라 수동 활성화가 필요했다. 이를 위해 AWS는 샘플 저장소를 통해 두 가지 경로를 제공한다: 신뢰 가능한 라이선스를 일회성으로 활성화하는 경량 스크립트(dry-run 후 --apply), 그리고 판매자 허용목록을 검증하고 이벤트 기반으로 grant를 생성·재시도하는 AWS CDK 자동화다. CDK 경로는 EventBridge 규칙이 Marketplace 계약 생성 이벤트를 감지해 Lambda 함수를 호출하는 구조로 동작한다.

WHY IT MATTERS

수십~수백 개 AWS 계정에 걸쳐 AI 모델 협상가를 적용하려면 grant 활성화를 누락하기 쉬운데, 활성화 전까지는 협상된 가격이 적용되지 않아 비용 관리에 직접적 영향을 준다. 멀티 계정 거버넌스를 운영하는 MLOps 팀이라면 모델 도입·갱신 시마다 반복되는 수작업을 줄일 수 있는 실질적 가이드다.

WHAT'S DIFFERENT

기존의 콘솔에서 수동으로 License Manager grant를 확인·활성화하던 방식 대비, 일회성 점검용 경량 스크립트와 판매자 검증·재시도까지 포함한 상시 이벤트 기반 CDK 자동화라는 두 가지 선택지를 제공한다.

01Meta GEM 2026, 광고 추천을 단일 중앙 모델로 통합 — 전환율 18.9%·CTR 12% 개선Meta’s Generative Ads Model (GEM): Scaling the Central Model and Compute Engine for Frontier Ads AI✍️ 블로그 · engineering.fb.comMeta가 자사 광고 추천시스템 파운데이션 모델 GEM의 2026년 버전을 공개했다.

기존에 Facebook, Instagram, Reels 등 각 서비스별로 분리돼 있던 최적화를 하나의 중앙 파운데이션 모델로 통합해 전체 깔때기(인지·고려·전환) 단계를 동시에 최적화한다. 핵심 아키텍처 Kunlun은 GPU 하드웨어와 공동 설계된 LLM 스타일 구조로, 2.5배 모델 복잡도 증가에서도 LLM과 유사한 스케일링 법칙을 확인했다. 또한 LoopFM이라는 사후학습 기법으로 GEM의 내부 표현과 사용자 이력 정보를 실시간 서빙 모델에 추가 연산·지연 없이 전달한다. 그 결과 전체 광고 영역에서 전환율 18.9%, 클릭률 12% 개선을 달성했다.

WHY IT MATTERS

수십억 명이 쓰는 Meta 광고 생태계 전반에 LLM식 스케일링 법칙을 적용해 실질적 비즈니스 성과로 연결시킨 사례로, 추천시스템에 트랜스포머 스케일링을 적용하는 산업적 방향성을 보여준다.

WHAT'S DIFFERENT

기존에는 Facebook, Instagram, Reels 등 서비스·목표별로 독립된 예측 시스템을 운영했으나, GEM 2026은 이를 하나의 중앙 파운데이션 모델로 대체해 전체 광고면에서 동시에 성능을 개선한다는 점이 다르다.

02Airbnb, CASTLE 공개 — 예약 세션 기반 합성 쿼리로 자연어 검색 콜드스타트 해결, CIKM 2026 채택CASTLE: training natural language search before the first real query✍️ 블로그 · medium.comAirbnb는 실제 사용자 쿼리가 없는 상태에서 자연어 검색 모델을 학습시켜야 하는 콜드스타트 문제를 해결하기 위해 CASTLE 프레임워크를 개발했다.

비식별화된 예약·검색 세션에서 게스트가 조회 후 예약한 리스팅(positive)과 조회만 하고 예약하지 않은 리스팅(negative)의 쌍을 추출하고, 이를 LLM에 입력해 positive는 만족하지만 negative는 만족하지 않는 쿼리를 생성하도록 지시한다. 이 방식으로 쿼리 생성과 관련성 라벨링을 동시에 해결하며, 라벨은 생성 과정 자체에서 정확성이 보장되어 별도의 사후 판정이 필요 없다. 기존 InPars, Promptagator 같은 방법은 KL divergence 기준 9.33~26.2로 실제 사용자 쿼리 분포와 괴리가 컸다.

WHY IT MATTERS

신규 검색 기능을 실제 트래픽 없이 출시해야 하는 모든 서비스가 겪는 콜드스타트 문제에 대해, 실제 사용자 행동 데이터를 활용한 합성 학습 데이터 생성 방식을 제시한다는 점에서 실무적 참고 가치가 크다.

WHAT'S DIFFERENT

기존 InPars, Promptagator 같은 passage 기반 방법은 쿼리 생성과 관련성 라벨 부여를 별도 단계로 처리해 LLM 판정이라는 추가 오차 요인을 수반했지만, CASTLE은 예약 세션의 contrastive listing 쌍을 이용해 쿼리 생성과 라벨링을 하나의 메커니즘으로 통합한다.
