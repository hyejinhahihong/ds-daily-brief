★01AWS, Agent Registry로 에이전트 툴 런타임 발견 지원 — 하드코딩 없이 MCP·A2A 동적 탐색Discover tools at runtime with AWS Agent Registry✍️ 블로그 · aws.amazon.comAWS Agent Registry는 MCP 서버, 에이전트, 에이전트 스킬을 카탈로그화하고 검색할 수 있는 관리형 서비스다.

기존에는 도구를 오케스트레이터에 모두 하드코딩해야 해 수십 개를 넘어가면 관리가 어렵고, 새 기능 추가마다 코드 변경과 재배포, 팀 간 조율된 릴리스가 필요했다. 이 글은 Discover → Instantiate → Execute 루프를 Amazon Bedrock AgentCore Gateway, A2A 에이전트, Registry, 오케스트레이터로 구성된 Python 샘플로 설명한다. 오케스트레이터는 자연어 쿼리로 Registry를 검색해 레코드 식별자, 설명, MCP/A2A 디스크립터를 받지만 인증 자격 증명은 별도 경로로 획득해야 한다. 매 요청마다 동적으로 발견된 도구만으로 임시 내부 에이전트를 구성하고 처리 후 폐기한다.

WHY IT MATTERS

수백 개의 내부 API를 노출하는 엔터프라이즈 시스템에서는 도구 이름 구분에 토큰을 낭비하거나 배포 병목이 발생하는데, 런타임 도구 발견은 이런 빌드타임 결합 문제를 완화할 수 있다.

WHAT'S DIFFERENT

기존의 하드코딩된 오케스트레이터(모든 도구를 사전 컴파일하는 방식) 대비, Registry 기반 검색으로 승인된 레코드를 런타임에 조회하고 엔드포인트만으로 클라이언트를 동적으로 구성한다는 점이 다르다.

WHY IT MATTERS

WHAT'S DIFFERENT

★01i14, AWS Trainium2에서 Laplace 3B 선형어텐션 모델 학습·서빙 — KV캐시 없이 29.5MB 고정 상태 구현Beyond the KV cache: Training and serving i14’s Laplace 3B linear attention model on AWS Trainium2 with native PyTorch✍️ 블로그 · aws.amazon.comi14는 트랜스포머의 KV 캐시 증가 문제를 해결하기 위해 Gated Linear Attention(GLA) 기반의 Laplace 3B 모델을 설계했다.

이 모델은 컨텍스트 길이와 무관하게 시퀀스당 29.5MB의 고정 크기 재귀 상태만 유지한다. AWS와 협력해 GPU용 Triton 커널을 표준 PyTorch 연산으로 재작성하고, TorchNeuron Native 백엔드를 통해 Trainium2에 이식했으며 GLA 구조와 Muon 옵티마이저를 유지했다. trn2.48xlarge 인스턴스 1대에서 초당 약 12만 토큰으로 학습했고, 1,280개 동시 시퀀스에서 초당 11,544개 출력 토큰을 서빙했다.

WHY IT MATTERS

KV 캐시 증가는 긴 대화나 문서를 다루는 에이전트 애플리케이션의 동시성과 비용에 직접적인 제약이 되는데, 고정 크기 상태를 가진 선형어텐션은 이 한계를 구조적으로 해소할 수 있다는 점에서 장기 실행 에이전트와 대용량 문서 분석에 의미가 크다.

WHAT'S DIFFERENT

기존 소프트맥스 어텐션의 학습 연산이 O(T²)로 증가하고 추론 시 KV 캐시가 컨텍스트에 비례해 커지는 것 대비, Laplace 3B는 GLA로 학습을 O(T)로 줄이고 추론 상태를 고정 크기로 유지하며, GPU 전용 Triton 커널 대신 표준 PyTorch 연산과 all_to_all 통신 재설계, 역전파 그래프 정적 언롤링으로 Trainium2에 맞게 이식했다.

02A Conditional No-Hair Theorem for Transformers: How Language Models Forget Their Prompt트랜스포머의 '조건부 무모론': 생성 토큰 t개 늘수록 프롬프트 영향력 t^-α로 소멸, 학습모델 α≈0.55-0.7📄 논문 · arxiv.org자기회귀 트랜스포머가 같은 이어쓰기 텍스트를 생성할 때, 서로 다른 두 프롬프트의 영향이 히든 상태에서 얼마나 남는지를 분석했다.

두 프롬프트 간 히든 상태 거리는 생성 토큰 수 t에 대해 대략 거듭제곱 법칙 t^-α로 감소하며, 학습된 모델은 α≈0.55-0.7로 빠르게 잊고 학습되지 않은 모델은 α≈0.2-0.5로 느리게 잊는다. 저자들은 프롬프트 길이 P와 깊이 L에 대해 이 차이가 O(P(log t)^{L-1}/t)로 상한이 잡힌다는 것을 유한 깊이 pre-LN softmax 트랜스포머에서 증명했다. 메커니즘은 기하학적으로, 문맥이 커질수록 프롬프트의 직접 영향이 희석되고, 이전 토큰이 읽은 프롬프트 정보를 전달하는 '릴레이'는 로그 배수만 추가할 수 있다. 정확히 풀리는 선형 릴레이 모델로 이 상한이 개선 불가능함을 보이고, 로짓 바이어스로 희석을 상쇄하면 망각이 멈추거나 역전되어 희석이 망각의 필요충분조건임을 확인했다.

WHY IT MATTERS

긴 문맥에서 모델이 초기 프롬프트(시스템 지시, 페르소나 등)를 왜 서서히 잊는지에 대한 이론적 근거를 제공해, 장문 생성이나 긴 대화에서의 지시 따르기 저하 문제를 설명하는 데 도움이 된다.

WHAT'S DIFFERENT

기존의 경험적 관찰에 그쳤던 '긴 문맥에서 지시를 잊는다'는 현상을 pre-LN softmax 트랜스포머에 대한 수학적 증명과 해석 가능한 선형 릴레이 모델로 뒷받침했다는 점이 다르다.

03Kronecker Delta Rule for Long Context Linear AttentionKronLSTM 공개 — Kronecker Delta Rule로 장문맥 선형 어텐션 안정화, DeltaNet 계열 능가📄 논문 · arxiv.org연구진은 연상 행렬 메모리를 위한 새로운 갱신 규칙인 Kronecker Delta Rule을 제안하고, 이를 xLSTM 계열에 적용한 KronLSTM을 제시했다.

이 규칙은 행렬 공간의 단일 방향으로만 메모리를 수정하여 기존 저장된 정보와의 간섭을 최소화하는 메모리 수정 메커니즘을 특징으로 한다. 메모리 동역학은 정상 분포로 수렴하는 마르코프 체인으로 수학적으로 기술되며, 메모리 행렬의 기대 노름이 입력 시퀀스 전체에서 균일하게 유계임이 증명되어 별도의 정규화 없이도 안정적이다. 실험 결과 KronLSTM은 (Gated) DeltaNet 계열을 포함한 기존 선형 어텐션 아키텍처와 경쟁력이 있거나 이를 능가하며, 특히 장문맥 벤치마크에서 강한 성능을 보였다.

WHY IT MATTERS

선형 어텐션의 고질적 문제인 메모리 안정성과 간섭 문제를 별도의 정규화 장치 없이 이론적으로 해결했다는 점에서, 장문맥 언어 모델링을 위한 효율적 아키텍처 설계에 실질적 지침을 제공한다.

WHAT'S DIFFERENT

기존 델타 규칙(DeltaNet) 기반 갱신이 메모리 전체를 수정하는 것과 달리, Kronecker Delta Rule은 행렬 공간의 단일 방향으로만 최소 침습적으로 메모리를 수정해 이전 정보와의 간섭을 줄인다.

01Measuring Mechanistic Uncertainty in Large Language Models via Causal RobustnessLLM 내부 메커니즘 안정성으로 불확실성 측정 — '인과적 강건성 마진' 제안, 오답일수록 마진 작아📄 논문 · arxiv.org이 연구는 모델 응답을 뒷받침하는 내부 메커니즘의 안정성으로 불확실성을 정의하는 '메커니즘적 불확실성' 개념을 제안한다.

핵심 지표인 인과적 강건성 마진은 모델 출력을 바꾸는 데 필요한 최소한의 내부 개입 크기로 정의되며, Jacobian Lens(Jlens) 개념 조향 벡터로 측정한다. 3개 오픈소스 모델과 5개 질의응답 데이터셋 실험 결과, 오답 및 불확실한 응답일수록 마진이 작아 내부 개입에 더 민감함을 보였고, 이는 기존 출력 기반 불확실성 지표를 보완했다. 또한 지식 주입 실험에서 올바르게 학습된 사실은 학습 후 마진이 커져, 인과적 강건성이 메커니즘에 근거한 불확실성 신호임을 시사했다.

WHY IT MATTERS

LLM 환각 문제 해결을 위해 출력 확률에만 의존하던 불확실성 추정을 모델 내부 구조 관점에서 보완할 수 있어, 고위험 도메인에서 신뢰도 평가의 해석 가능성을 높일 잠재력이 있다.

WHAT'S DIFFERENT

기존 출력 기반(output-based) 불확실성 정량화 방법과 달리, 내부 개입에 대한 민감도를 측정하는 인과적 강건성 마진을 도입해 두 접근이 상호 보완적임을 보였다.

01AWS·Keyfactor, X.509 PKI로 AI 에이전트 신원 인증 — MCP의 인증 공백 메운다Securing AI agent identity with X.509 PKI on AWS✍️ 블로그 · aws.amazon.comAI 에이전트가 DB·API 등 민감한 작업에 접근할 때 요청자를 증명하고 위조를 막기 위해 X.509 PKI 기반 암호화 신원 체계가 필요하다고 설명한다.

멀티 에이전트 프레임워크가 널리 쓰는 Model Context Protocol(MCP)은 전송 방식에 독립적으로 설계되어 인증 표준이 내장되어 있지 않다는 공백이 있다. 이를 메우기 위해 AWS는 Keyfactor EJBCA와 결합한 참조 아키텍처를 제시하며, 서명된 요청 봉투, 사용자 서명 위임 승인, RFC 8693 기반 범위 제한 토큰, 실시간 OCSP 폐기 확인 등 네 가지 보안 메커니즘을 사용한다. 솔루션은 Amazon Bedrock과 AWS Strands Agents SDK로 LLM 추론을 수행하며, DB를 보호 대상 리소스로 삼지만 동일 인증 패턴을 모든 MCP 호환 도구 서버에 적용할 수 있다.

WHY IT MATTERS

다중 에이전트 시스템이 외부 도구·데이터에 접근하는 구조가 보편화되면서, 인증 표준이 없는 MCP의 보안 공백은 에이전트 가장·토큰 재생·무단 도구 호출 같은 실제 위협으로 이어질 수 있다. 엔터프라이즈가 제로트러스트 요건을 만족시키며 AI 에이전트를 운영하려면 이런 암호화 신원 계층 설계가 선행 과제가 된다.

WHAT'S DIFFERENT

API 키 공유나 OAuth 토큰을 에이전트 체인에 그대로 전달하는 기존 방식 대비, 서명 기반 proof-of-possession과 사용자 서명 위임, 범위 제한 토큰, 실시간 폐기 확인을 결합해 자격 증명 노출과 위조 위험을 줄인다는 점이 다르다.

01‘세컨드 유저 테스트’ — 다른 학생이 재현·검증하자 AI 생성 연구 설계 결함 드러나The Second-User Test📰 뉴스 · oreilly.com저자는 중국 충칭 Force Academy에서 학생이 완성한 프로젝트를 다른 학생에게 넘겨 재현·검증·수정하게 하는 ‘핸드오프’ 방식을 교육에 활용한다.

AI 노동경제학 논문 사례에서, 주도 학생이 모델과 분석을 만든 뒤 다른 학생이 독립적으로 분석을 재실행하고 데이터 버전·연결 규칙을 검증하도록 했다. 그 과정에서 재현성 문제(워크플로가 한 학생의 기억에 의존)와 더 심각한 측정 설계 문제(두 지표가 같은 설문 문항을 공유해 상관관계가 왜곡됨)가 드러났다. 결국 팀은 지표를 재구성하고 모호한 항목을 제거했으며, 데이터 추적이 가능하도록 전체 분석 과정을 재설계했다.

WHY IT MATTERS

생성형 AI로 그럴듯한 초안을 값싸게 만들 수 있게 되면서, 완성도 높은 결과물이 곧 이해를 증명하지 않는다는 점이 교육과 실무 모두에서 중요한 문제로 떠오른다. 제3자가 재현·검증하는 절차는 AI 지원 작업의 숨은 가정과 설계 결함을 드러내는 실질적 품질 검증 장치가 될 수 있다.

WHAT'S DIFFERENT

기존의 코드 실행 여부나 결과물 포장 상태를 확인하는 단순 재현 테스트와 달리, 이 핸드오프 방식은 측정 지표 설계 자체의 타당성까지 검토하게 만들어 절차적 검증을 실질적 연구 재설계로 이어지게 한다.

단일 기능 대신 모든 향후 AI 기능이 올라갈 3계층 공통 플랫폼을 먼저 만들었고, Cohere Embed v4를 Amazon Bedrock에서 사용해 20억 개 문서를 임베딩했다. 벡터 저장소, 검색 로직, 생성 컨텍스트 모두 테넌트 단위로 범위를 제한했고, 에이전트 권한도 공유 서비스 역할이 아닌 요청 사용자 기준으로 실행 중에만 부여되도록 설계했다. 이 기반 위에서 Complaint Triage Assistant를 실제 프로덕션에 적용해 아키텍처를 검증했다. 그 결과 사용 사례별 배포 시간이 50% 단축됐다.

WHY IT MATTERS

14,000개 이상 고객사가 의료기기·제약·식품 제조 분야 규제 데이터를 공유하는 멀티테넌트 SaaS에서 AI를 도입할 때, 데이터 유출 하나가 기능 이점을 훨씬 능가하는 규제 리스크로 이어질 수 있음을 보여준다. 격리가 타협 불가한 환경에서 AI를 설계해야 하는 모든 SaaS 사업자에게 적용 가능한 아키텍처 참고 사례다.

WHAT'S DIFFERENT

기능 단위로 AI를 개별 구축하던 기존 방식 대신, 수십 개 애플리케이션에 걸친 공통 수평 플랫폼을 먼저 구축한 뒤 수직 기능을 끼워 넣는 방식을 택했으며, 공유 서비스 역할 기반 정적 권한 대신 요청 사용자 범위로 실행 중에만 활성화되는 에이전트 권한 모델을 적용했다.
