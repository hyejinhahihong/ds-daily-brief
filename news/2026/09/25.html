★01AWS, AgentCore Gateway·MCP로 계정 간 데이터 이동 없는 멀티어카운트 AI 에이전트 구축법 공개Build a multi-account AI agent with AgentCore Gateway and MCP✍️ 블로그 · aws.amazon.comAWS는 여러 AWS 계정에 흩어진 데이터를 복제하지 않고도 AI 에이전트가 조회할 수 있는 멀티어카운트 아키텍처를 소개한다.

각 사업부(LOB) 계정은 자체 데이터와 도구를 MCP 서버로 노출하고, 중앙 플랫폼 계정의 AgentCore Gateway가 이를 하나의 엔드포인트로 통합해 도구 탐색과 호출을 제공한다. 플랫폼 계정은 Amazon Bedrock을 통한 LLM 추론, Guardrails 적용, 단일 과금 경계를 담당하며, AgentCore Identity와 Okta로 인증을, AgentCore의 Cedar 기반 Policy로 세밀한 인가를 처리한다. Gateway는 MCP 서버 집계 외에도 HTTP 타깃, 추론 게이트웨이 역할까지 지원해 중앙 통합 지점으로 기능한다.

WHY IT MATTERS

기업이 데이터 소유권과 격리를 유지하면서도 여러 부서의 데이터를 아우르는 에이전트를 만들려면 계정 간 IAM 얽힘과 데이터 복제 문제를 피해야 하는데, 이 구조는 데이터가 원래 계정에 머문 채 요청 시점에만 필요한 정보를 흐르게 해 거버넌스와 확장성을 동시에 확보한다.

WHAT'S DIFFERENT

개별 LOB의 MCP 서버에 직접 연결하거나 원시 AWS 리소스를 노출하던 기존 방식과 달리, AgentCore Gateway를 단일 진입점으로 두어 인증·인가·관측성을 게이트웨이 계층에서 코드 밖에서 통합 처리한다.

02Meta, AI 글래스에 '프라이빗 프로세싱' 도입 — 기밀 컴퓨팅으로 클라우드 처리도 Meta가 못 보게 암호화Bringing Private Processing to Meta AI Glasses✍️ 블로그 · engineering.fb.comMeta는 AI 글래스가 통역, 노트 요약 등 고급 기능을 수행하려면 온디바이스로는 부족해 클라우드의 대형 모델이 필요하다고 설명한다.

이를 위해 개인 맥락 데이터를 클라우드에서 처리하면서도 Meta조차 접근할 수 없도록 하는 Private Processing이라는 기밀 컴퓨팅 인프라를 도입했다. 이는 신뢰 경계를 클라우드 데이터센터의 기밀 가상머신(CVM)까지 확장해, TEE(Trusted Execution Environment) 하드웨어로 CVM 메모리를 암호화하고 원격 증명(remote attestation)으로 실행 코드의 무결성을 검증한다. 이 방식은 2025년 WhatsApp과 Meta AI 앱에 먼저 도입됐던 것을 AI 글래스로 확장한 것이다.

WHY IT MATTERS

글래스처럼 상시 착용되며 개인 맥락을 깊이 파악하는 기기가 클라우드 대형 모델과 연동되려면, 프라이버시와 성능을 동시에 만족시키는 인프라 설계가 필수적이다. 이는 향후 개인화된 상시 AI 비서 아키텍처의 프라이버시 표준을 가늠하는 사례가 될 수 있다.

WHAT'S DIFFERENT

기존 WhatsApp·Meta AI 앱의 Private Processing 경험을 바탕으로, 이번에는 CPU와 GPU를 아우르는 TEE 신뢰 경계를 AI 글래스라는 새로운 폼팩터의 대규모 개인 맥락 처리로 확장했다는 점이 다르다.

01Support-Compiled Feature Folding: More Evidence at Lower Memory Across Tabular Foundation ModelsSCFF, 표 기반모델 특징 스케일링 해결 — 18개 데이터셋서 정확도↑ 메모리 최대 34.3배 절감📄 논문 · arxiv.org표 기반 파운데이션 모델은 열이 늘수록 특징 간 쌍 결합 계산이 2차 함수로 증가하는 반면, 특징 선택은 정보를 버려 메모리를 아끼는 딜레마가 있다.

이 논문은 학습 없이 동작하는 추론 프레임워크 Support-Compiled Feature Folding(SCFF)을 제안해, 지지도 순으로 정렬된 특징을 인코더의 제한된 리프에 통과시키고 잔여 증거를 검증한 뒤 메시지를 병합해 단일 예측을 수행한다. 이를 통해 2차 함수적 특징 상호작용 연산을 폭에 비례하는 선형 연산으로 바꾸면서도 백본은 그대로 고정한다. AMLB-29, TabZilla, TabArena의 18개 wide-table 데이터셋에서 6개 백본 모두 정확도와 NLL이 개선되었고, 상대 오류는 최대 26.1% 감소, GPU 메모리는 중앙값 2.09~2.36배, 최대 피크는 34.3배까지 절감되었다. 동일한 메모리 상한에서는 절약된 예산으로 더 많은 증거를 보존해 TabICLv2와 TabPFN-3에서 최대 4.06점, 3.72점 정확도 향상을 보였다.

WHY IT MATTERS

열 수가 많은 표 데이터에서 파운데이션 모델을 확장할 때 메모리 병목이 실전 적용의 걸림돌인데, 백본 재학습 없이 추론 단계에서 이를 해결하면 기존 배포된 모델을 그대로 활용할 수 있어 실용적 가치가 크다.

WHAT'S DIFFERENT

WHAT'S DIFFERENT

기존의 인과적 감사(causal audit)는 개입 후 성능 저하 여부만 확인했지만, 이 연구는 패치가 특정 반사실적 답으로 전환되어야 한다는 알려진 예측 목표를 사전에 설정해 검증한다는 점이 다르다. 또한 텍스트만 편집해 답 변화를 관찰하는 기존 행동적(behavioral) 충실도 지표와 달리, 잔차 스트림 활성화 패칭으로 인과관계를 직접 측정한다.
