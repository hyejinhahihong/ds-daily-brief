★01AWS, Bedrock AgentCore로 MCP Apps 구현 — ChatGPT·Claude서 동일한 HTML 위젯 UI 제공Build interactive MCP Apps using Amazon Bedrock AgentCore✍️ 블로그 · aws.amazon.comAWS는 ChatGPT, Claude 등 여러 AI 호스트에서 특정 서비스에 종속되지 않고 대화형 UI를 제공하는 방법으로 MCP Apps와 Amazon Bedrock AgentCore를 소개했다.

MCP Apps는 Model Context Protocol을 확장해 AI 호스트 내부에 직접 렌더링되는 인터랙티브 HTML 위젯을 지원하며, AgentCore Runtime은 세션 격리된 서버리스 MCP 호스트를, AgentCore Gateway는 이를 단일 보안 엔드포인트로 노출한다. 예시 앱인 'Unicorn Rentals'는 유니콘 목록 조회, 예약, 예약 확인, 반납까지 자연어 대화로 처리하며, 필요에 따라 카드형 위젯과 텍스트 응답을 혼용해 보여준다. 전체 로직은 AWS Lambda와 Amazon DynamoDB를 사용하는 단일 MCP 서버가 AgentCore Runtime과 Gateway를 통해 서비스한다.

WHY IT MATTERS

AI 에이전트가 서비스 접점의 중심이 되면서, 텍스트 응답을 넘어 호스트에 종속되지 않는 리치 UI를 제공하는 표준화된 방법이 필요해지는 상황을 보여준다.

WHAT'S DIFFERENT

특정 AI 호스트에 종속된 커스텀 통합 대신, 호스트에 구애받지 않는 MCP Apps 표준과 AgentCore의 보안·서버리스 인프라를 결합해 ChatGPT와 Claude에서 동일한 경험을 제공한다는 점이 다르다.

저자는 이를 '예외 표류(exception drift)'라 부르며, 임시 운영 상태가 권한 범위나 지속 기간을 벗어나 조용히 표준 실행 방식으로 굳어지는 현상이라고 설명한다. 조직은 정상 운영, 인시던트 선언, 임시 예외 창, 종료 검토, 정상 복귀라는 예측 가능한 단계를 거치지만, 대부분 예외 선언과 승인은 잘하는 반면 예외를 실제로 회수했다는 증거를 확인하는 '종료' 단계는 소홀히 한다. 근본 원인은 아키텍처적인 것으로, 대부분의 에이전트 플랫폼이 조직의 운영 모드(정상/인시던트/복구)를 아이덴티티나 권한처럼 런타임 입력으로 다루지 않고 런타임 바깥의 것으로 취급하기 때문이라고 지적한다.

WHY IT MATTERS

WHAT'S DIFFERENT
