★01HPE Zerto, Amazon Bedrock 기반 에이전틱 트러블슈팅 시스템 구축 — 온프레미스 배포로 재해복구 자연어 진단 지원How HPE Zerto built an agentic troubleshooting system with Amazon Bedrock✍️ 블로그 · aws.amazon.comHPE Zerto는 하이브리드·멀티클라우드 환경의 데이터 보호 및 재해복구 운영을 돕기 위해 Amazon Bedrock 기반 에이전틱 트러블슈팅 시스템을 개발했다.

이 시스템은 Zerto 제품 내 온프레미스 환경에 파드 형태로 배포되어 기존 UI에서 자연어로 상호작용하며, 운영 신호와 환경 컨텍스트, 제품 지식에 안전하게 접근한다. Amazon Bedrock을 선택한 이유는 보안·거버넌스, 다중 파운데이션 모델 선택 유연성, 가드레일·관측성·지식 검색 등 AWS 서비스와의 운영 통합성 때문이다. Amazon Bedrock Guardrails로 프롬프트와 출력이 회사 정책 및 컴퓨트 보안 요구사항에 부합하도록 콘텐츠 보안을 강제한다.

WHY IT MATTERS

재해복구·사이버 복원력 분야처럼 지연 비용이 큰 운영 환경에서 파편화된 알림·문서를 자연어 질의로 통합해 빠른 의사결정을 지원하는 실사례로, 엔터프라이즈 온프레미스 AI 에이전트 배포 아키텍처의 참고 모델이 된다.

WHAT'S DIFFERENT

기존에는 운영자가 대시보드, 보고서, 지식 소스를 수동으로 오가며 정보를 취합해야 했으나, 이 시스템은 라이브 환경 상태에 근거해 추론·행동·응답까지 수행하는 에이전틱 방식으로 지원 티켓 생성 없이 즉시 문제를 해결한다.

01AWS, SageMaker G7(Blackwell) vs G5·G6 벤치마크 — 30B MoE 모델서 GPU 절반으로 가격 대비 성능 우위Benchmarking small LLM inference on SageMaker AI: G7 vs G5 and G6✍️ 블로그 · aws.amazon.comAWS는 SageMaker AI Inference에서 Qwen3-Coder-30B와 NVIDIA Nemotron-3-Nano-30B 두 개의 30B급 MoE 모델을 대상으로 G5(A10G), G6/G6e(L4, L40S), G7(Blackwell RTX PRO 4500) 인스턴스를 비교 벤치마크했다.

G5와 G6는 GPU 4개·96GB 메모리 구성인 반면 G7은 GPU 2개·64GB로 절반의 하드웨어만 사용한다. 코딩 어시스턴트 사례는 DJL LMI 컨테이너로 직접 벤치마크했고, 엔터프라이즈 어시스턴트 사례는 vLLM 기반 SageMaker Generative AI Inference Recommendations 기능으로 자동 벤치마킹·구성 선택을 수행했다. 그 결과 G7이 더 적은 GPU 수와 메모리로도 처리량, 지연시간, 토큰당 비용에서 개선을 보여줬다.

WHY IT MATTERS

동일 30B급 MoE 모델을 여러 GPU 세대·서빙 스택에서 비교한 실측 데이터는 실제 배포 시 인스턴스 선택 의사결정에 바로 활용할 수 있는 근거를 제공한다.

WHAT'S DIFFERENT

기존 G5·G6 세대 대비 G7은 GPU 개수와 총 메모리를 절반으로 줄이면서도 가격 대비 성능이 우수함을 보여준 점이 다르다.

02Privacy Failure in Split-LLM Training, The Returned Gradient Nullifies the DecoysSplit-LLM 학습, 역전파 그래디언트가 디코이 마스킹 무력화 — 4096/4096 실제 행 전수 식별📄 논문 · arxiv.org두 노드로 분리된 LLM 학습 시스템에서, 신뢰 노드(TLN)가 비공개 손실을 이용해 그래디언트를 클라우드 노드(UCN)로 되돌려줄 때 디코이 행의 그래디언트가 정확히 0이 되어 실제 행이 그대로 드러나는 취약점을 발견했다.

사전에 정한 프로토콜로 검증한 결과 9개 시드 전 구간에서 프레임당 4,096개 행 전부가 식별되었고, 셔플 대조군에서는 누출이 전혀 검출되지 않았다. 프레임 내용에 대한 공격으로는 상수 추측 기준 대비 100개 토큰당 약 1개를 추가로 복원했으며(+0.65~1.50%p), 모델 품질을 예산 내로 유지하는 설정에서도 동일한 결과가 재현되었다. 순방향 채널 프라이버시 검사와 품질 검사는 통과했지만 반환 그래디언트를 포함하면 동일 검사에서 실패했다. 각 행의 그래디언트에 클리핑과 노이즈를 적용하자 held-out 교차엔트로피 약 0.01 nats 비용으로 누출이 차단되었다.

WHY IT MATTERS

기존 프라이버시 평가가 순방향 채널만 검증하고 역방향 그래디언트 채널을 누락하면 통과 판정 자체가 무의미해질 수 있음을 보여주는 사례로, split-training 시스템의 보안 감사 범위 재설계가 필요함을 시사한다.

WHAT'S DIFFERENT

기존 split-LLM 프라이버시 검증이 순방향(활성화) 채널의 디코이 삽입 여부만 확인했던 것과 달리, 이 연구는 반환되는 손실 그래디언트 채널까지 포함해 검증했을 때 동일 시스템이 실패함을 사전 등록된 프로토콜(주입 강도 실험, 셔플 대조군, 사전 임계값)로 입증했다.

01Pathway, 뇌 구조 모방한 BDH 아키텍처 발표 — SageMaker HyperPod로 학습, 체인오브소트 없이 잠재공간 추론Pathway’s brain-inspired architecture development on Amazon SageMaker HyperPod✍️ 블로그 · aws.amazon.comPathway는 트랜스포머 대신 뇌의 뉴런 연결 방식을 모사한 BDH(Dragon Hatchling) 아키텍처를 공개했다.

이 모델은 텍스트 형태의 중간 추론 과정을 생성하지 않고 잠재공간에서 반복 계산을 통해 추론을 수행하며, 테스트 시점 가중치 업데이트 없이 문맥 안에서 상태를 조정한다. BDH-CQ 변형은 재귀적 잠재 상태 내부에서 반복 계산을 수행해 추론 중 내부 메모리를 갱신하고 후보 답만 디코딩하며, 별도의 파인튜닝이나 재학습이 필요 없다. Pathway는 PyTorch와 통합된 이 아키텍처를 Amazon SageMaker HyperPod를 활용해 확장 학습했다.

WHY IT MATTERS

트랜스포머는 고정 컨텍스트 윈도우, 늘어나는 KV 캐시, catastrophic forgetting 등 구조적 한계로 긴 시간에 걸친 일관된 추론과 지식 갱신에 취약한데, BDH는 이런 한계를 근본적으로 다른 아키텍처로 우회하려는 시도라는 점에서 주목할 만하다.

WHAT'S DIFFERENT

체인오브소트처럼 토큰을 순차 생성해 다시 입력하는 기존 트랜스포머 추론 방식과 달리, BDH는 텍스트 추론 흔적을 생성하지 않고 잠재공간에서 직접 반복 계산으로 답을 도출한다.

WHY IT MATTERS

WHAT'S DIFFERENT

SAM 3 등 기존 텍스트 프롬프트 세그멘테이션 모델 대비 시간적 환각과 온톨로지 오분류 문제를 명시적으로 해결하며, 포인트 상호작용에 국한됐던 SeC 아키텍처를 텍스트 프롬프트 방식으로 확장한 점이 차별점이다.

01Causal Foundation Models인과추론도 파운데이션 모델 시대로 — CFM, 재학습 없이 in-context 학습으로 처치 효과 추정📄 논문 · arxiv.org이 논문은 새로운 문제마다 인과 메커니즘 제안, 추정기 선택, 학습이라는 맞춤형 파이프라인이 필요했던 기존 인과추론 방식을 설명한다.

반면 머신러닝 전반은 대규모로 한 번 사전학습한 뒤 새로운 과제에 적용하는 파운데이션 모델 패러다임으로 이동했다. 저자들은 이 패러다임을 인과추론에 도입한 인과 파운데이션 모델(CFM)을 소개하는데, CFM은 모델 업데이트 없이 in-context learning만으로 새로운 데이터셋에서 평균 처치 효과 같은 인과량을 추정한다. 논문은 인과추론과 머신러닝의 필요 배경을 정리한 뒤 CFM을 설명하며, 예제 코드와 Jupyter 노트북도 함께 제공한다.

WHY IT MATTERS

매번 새로 파이프라인을 구축해야 했던 인과추론 실무에 파운데이션 모델식 접근이 적용되면, 반복적인 모델링·학습 비용을 크게 줄일 수 있어 실무자와 연구자 모두에게 유용한 방향이다.

WHAT'S DIFFERENT

기존 인과추론이 문제마다 메커니즘 설계와 추정기 학습을 새로 수행해야 했던 것과 달리, CFM은 사전학습된 모델을 재학습 없이 in-context learning으로 새 데이터셋에 바로 적용한다는 점이 다르다.
